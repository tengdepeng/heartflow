## 1. 实现方案概述

本次改造的核心是**把世界壳的「2D↔3D」二元按键升级为一颗常驻的「三态循环键」**，并让心流页成为「双珠同框」的专注中心。三态键直接驱动既有的 `worldShell.surfaceState`（`hall-3d`/`map-2d`/`screen`），同时废弃旧的 `shellConfig.starsMode/courtyardMode` 双写机制，使三态键、`SwitchPanel`、反引号/长按触发器三者共用 `surfaceState` 单一真源、天然同步。幕僚珠不新增第二实例，而是在全局唯一的 `MirrorSelf`（`App.vue` 挂载）上新增 `homeCentered` 透传模式：当路由为 `/` 时，珠以 `fixed + translate(-50%, calc(-50% - var(--column-offset)))` 抬到计时珠正上方，与 `Home.vue` 中维持居中的 `JadeBead` 形成「幕僚珠偏上、计时珠正下」的纵向珠列；拖拽/隐藏逻辑完全复用既有 `dragPos`/`companion-widget` 持久化，拖离后自由浮动、不计较珠列塌缩。改动面极小——仅 `FloatingNavBar.vue`、`MirrorSelf.vue`、`App.vue` 三处，无新增依赖、无新增 store 方法（复用既有 `setSurfaceState`）。

## 1.1 框架选型说明

- **沿用 Vue3 SFC + `<script setup lang="ts">`**：所有改动均为既有组件内 props/computed/模板的调整，无需引入新框架或新渲染范式。
- **沿用 Pinia（`useConfigStore`）**：`surfaceState` 已是 `worldShell` 状态字段，且 `config.ts` 已提供 `setSurfaceState()`（深层 `watch` 自动持久化）。本方案不新增任何 store action，仅消费既有能力。
- **无新依赖**：不引入 React/MUI（宪法硬约束），不引入动画/状态库；三态切换过渡复用 `SurfaceStage` 既有 `surface-fade` 过渡（P2-3 可选）。

### 3.3 `FloatingNavBar` 三态键所需 computed / 映射

```ts
// 三态循环顺序（固定，单击前进一态）
SURFACE_CYCLE: SurfaceState[] = ['hall-3d', 'map-2d', 'screen']

// 当前态 / 下一态（P0-1 验收②依赖）
surfaceState : computed(() => configStore.config.worldShell.surfaceState ?? 'screen')
cycleIndex   : computed(() => { const i = SURFACE_CYCLE.indexOf(surfaceState.value); return i < 0 ? 2 : i })
nextSurface  : computed(() => SURFACE_CYCLE[(cycleIndex.value + 1) % 3])

// 图标 / 文案 / tooltip / aria 映射（P0-2 验收①依赖）
SURFACE_META : Record<SurfaceState, { label: string; tip: string; aria: string }> =
  'hall-3d' → { label:'3D',  tip:'3D 壳 · 点击切 2D 平面',        aria:'切换为 2D' }
  'map-2d'  → { label:'2D',  tip:'2D 壳（扁平）· 点击收起全隐藏',  aria:'收起世界壳' }
  'screen'  → { label:'收起', tip:'已收起 · 点击回 3D 壳',          aria:'展开 3D 壳' }
currentMeta : computed(() => SURFACE_META[surfaceState.value])

// 3D 高亮（复用既有 .is-3d 描金语言，P0-2 验收②）
is3dHighlight: computed(() => surfaceState.value === 'hall-3d')   // 取代原基于 starsMode/courtyardMode 的 is3d

// 单一动作（P0-3 验收①）
function cycleSurface(): void { configStore.setSurfaceState(nextSurface.value) }

// === 移除项 ===
//   starsMode / courtyardMode / modeToggleVisible / is3d(旧) / toggle2d3d  全部删除
```

### 3.4 `MirrorSelf.wrapperStyle` 新优先级（homeCentered 插入点）

```text
embedded                                   → 相对定位 {}（内嵌幕僚坞）
dragPos（被拖动过，自由浮动）               → fixed @ dragPos   ★ dragPos 升至 centered 之上，确保"拖动即接管"（D5/D6）
homeCentered（route==='/'）                 → fixed; left:50%; top:50%;
                                             transform: translate(-50%, calc(-50% - var(--column-offset, 220px)))
centered（activeShell==='courtyard' 非Home）→ fixed 居中 translate(-50%,-50%)
hallAnchor                                  → fixed @ 屏侧锚点
默认                                         → 右下常驻 (right:32px; bottom:80px)
```

> 关键：**`dragPos` 置于 `homeCentered`/`centered` 之上**（与既有"centered > dragPos"顺序相反）。
> 理由：D5 明定"拖动时 dragPos 接管变 fixed"，且 `canDrag()` 对非 embedded 恒真，旧顺序会使居中态拖拽被吞；新顺序使 Home 中心珠与宅院居中珠的拖离行为一致、可自由重定位并持久化（P0-5/D6）。

## 4. 程序调用流程

### 4.1 三态键单击 → 状态 → 重渲染

```
用户单击右下浮岛三态键
  └─ cycleSurface()                         [FloatingNavBar.vue]
       └─ configStore.setSurfaceState(nextSurface.value)
            ├─ 写入 config.worldShell.surfaceState（深层 watch 自动持久化）
            ├─ SurfaceStage.surfaceState(computed) 响应变化
            │    └─ surfaceState!=='screen' → 渲染 Hall3DSurface / Map2DSurface
            │       （配 surface-fade 过渡，P2-3 可选）
            │   surfaceState==='screen'  → v-if 为假，仅留路由内容 + CanvasRoom 粒子
            ├─ SwitchPanel.surfaceState(computed) 响应变化 → 当前卡片 active 高亮同步
            └─ FloatingNavBar.currentMeta / is3dHighlight 响应 → 图标/文案/tooltip/aria 随态更新

共存约束（D2）：
  - 反引号键 / 长按空白区 → useLayerSwitchTrigger → useLayerSwitch.toggle/open 仅打开 SwitchPanel，
    不直接写 surfaceState；与三态键只读同一真源、互不覆盖。
  - SwitchPanel 仍负责底层 activeShell 氛围切换（pickBottom→setActiveShell），与中层 surfaceState 解耦并存。
```

### 4.2 Home 路由下 MirrorSelf homeCentered 定位

```
App.vue：homeCentered = (route.path === '/')   [新增 computed，参照 L553 $router / L567 activeShell]
  └─ <MirrorSelf :homeCentered="homeCentered" ... />   [模板 L174–178 透传]

MirrorSelf.wrapperStyle（homeCentered 分支）：
  position: fixed; left:50%; top:50%;
  transform: translate(-50%, calc(-50% - var(--column-offset, 220px)))
    → 珠中心落在「视口中心上移 --column-offset」处。

Home.vue：JadeBead 维持 .home-focus 纵向居中（其自身 flow，中心≈视口中心）。
  → 视觉珠列：幕僚珠（中心-220px）在上，计时珠（中心）在下，净空≥阈值（P0-4 验收②）。

纵向间距保证（D5）：
  --column-offset = 幕僚珠半高 + 净空 + 计时珠半高（按真实尺寸校准）
    桌面：27(54/2) + 40 + 87(280px 玉盘实体半径≈87，取保守值) < 220 ✓
    移动：24(48/2) + 36 + 56(180px 玉盘实体半径≈56) < 150 ✓
  （具体像素值见 §8 待明确①，按真实渲染目视校准）

拖离回退（D6）：
  用户拖动幕僚珠 → onPointerMove 写 dragPos → wrapperStyle 命中 dragPos 分支（fixed 自由浮动）
  → JadeBead 位置不变、珠列不塌缩；恢复/归位由用户拖回或 P2-4 一键归位。

隐藏/恢复（D5/D8）：
  hideBead() → hidden=true → v-show 隐藏包裹层、出恢复药丸（companion-widget 持久化 hidden）
  → 计时珠 JadeBead 不受影响、照常显示（"两珠并存不合并"，D8：仅幕僚珠可隐藏）
```

## 7. 共享知识 / 跨文件约定

1. **`surfaceState` 三态常量**：类型 `SurfaceState`（`src/types/index.ts:487`，取值 `'screen' | 'hall-3d' | 'map-2d'`）。循环顺序 `SURFACE_CYCLE = ['hall-3d','map-2d','screen']` 定义在 `FloatingNavBar.vue`，与 `SwitchPanel.surfaceOptions`（L65–69）所列三态保持一致语义（三者共用同一类型，避免漂移）。
2. **单点真源**：三态键、`SwitchPanel`、`useLayerSwitchTrigger` 三者只读 `worldShell.surfaceState`，**互不写对方状态**——这是天然同步（D2/P0-3）的根基，后续任何新增切换入口都必须走 `setSurfaceState`，禁止另起字段。
3. **`companion-widget` 持久化键**：`MirrorSelf.vue:226`（`storage.getKV/setKV('companion-widget', {x,y,hidden})`）。homeCentered 模式**不新增任何持久化键**，拖拽落点复用既有 `dragPos`→`x/y` 字段；隐藏复用 `hidden` 字段。
4. **z-index 令牌（呼应 `docs/空间容器布局契约.md` 二）**：
   - 幕僚珠：`wrapperStyle.zIndex = 'var(--z-jade, 20)'`（契约 `--z-jade:20`）——保持。
   - 计时珠：`JadeBead.vue .jade-bead-container { z-index:10 }`（位于 `.home-focus` z:1 内）——保持。
   - 中层表面：`SurfaceStage .surface-stage z:5`、`.shell-hit-layer z:5`。
   - **约束**：新增任何浮层必须消费 `--z-*` 令牌，禁止裸写 `z-index` 数字（契约红线）。本次珠列布局全部复用既有令牌，无新增。
5. **`--column-offset` 响应式变量**：定义在 `MirrorSelf.vue` scoped 样式（`.mirror-self-wrapper { --column-offset: 220px }`，`@media(max-width:640px) .mirror-self--home-centered { --column-offset: 150px }`）；`wrapperStyle` 内联 `transform: translate(-50%, calc(-50% - var(--column-offset, 220px)))`。用 CSS 变量而非 JS 写死，既响应式又不在脚本硬编码布局像素（P0-6）。
6. **拖拽前置条件**：`canDrag()`（`MirrorSelf.vue:257`）仅 `embedded` 为 false 时可拖；homeCentered 珠 `embedded=false`，故默认可拖，与 D5"拖动时 dragPos 接管"一致。

## 8. 待明确事项（仅架构师无法定的技术细节点）

1. **`--column-offset` 精确像素值**：桌面 `220px` / 移动 `150px` 为 D5 建议区间（210–230）的初值，需按真实渲染的珠体尺寸目视校准，确保两珠**珠体净空 ≥ 建议阈值（桌面建议 ≥40px）**。`MirrorSelf` 珠体（`.ms-orb` 桌面 54px / 移动 48px）与 `JadeBead` 玉盘实体半径（280px→≈87px、180px→≈56px）的差值需在真机上复测。
2. **移动端更窄断点微缩**：`Home.vue` 已有 `@media(max-width:480px)` 规则（L746–783，玉盘 180px、净空压缩）；`MirrorSelf` 仅在 `≤640px` 设 48px 珠体。需确认 `≤480px` 或极矮视口下珠列是否仍需进一步微缩、净空是否仍不重叠（D7 已原则性要求"微缩但不重叠"）。
3. **`solid/video/custom` 壳下的"空表面"体验**：D3 要求这些壳下三态键仍三态循环写 `surfaceState`，但 `Hall3DSurface`/`Map2DSurface` 对 `solid/video/custom` 暂无内容（既有现状）。本次键只写状态、不新增表面渲染。需产品/主理人确认用户可接受"键已切到 3D/2D 但中层无可见内容"的过渡态，或在 UI 上标注"该壳 3D/2D 待实现"（不阻塞本增量）。
4. **`Home.vue` L774 移动端 `.mirror-self { display: none }`**：该规则属 Home 的 scoped 样式，按 Vue scoped 隔离机制**不会**作用于全局 `App.vue` 挂载的 `MirrorSelf`（跨组件不命中），实际为惰性代码。但为避免后续维护歧义、并明确保障心流页移动端珠可见，建议删除该行或显式加 `:deep()` 注释说明。列为低优先清理项（T6）。
5. **中层表面之上的幕僚珠交互**：心流页若 `surfaceState=hall-3d/map-2d`，幕僚珠位于中层表面（`z:5`）之上（`z:20`）仍可见且可拖拽；表面 `.shell-hit-layer`（`z:5`, `pointer-events:auto`）会拦截珠之外的指针，但珠自身 `pointer-events` 正常（珠在上层）。仅需联调确认"珠在中层表面之上"的拖拽手感，无需架构改动（T7 覆盖）。
