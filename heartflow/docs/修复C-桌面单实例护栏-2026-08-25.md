## 缺口回顾（来自缺口查缺报告）
- `project/src-tauri/Cargo.toml` 无 `tauri-plugin-single-instance`。
- `tauri.conf.json` 仅一个 `windows` 条目、无单实例配置。
- `src-tauri/src` 入口未注册任何单实例钩子。
- 结论：**双击 exe 可开多个窗口**（缺口查缺报告已确认 `multiWindowAllowed: true`，代码层结论）。

## 修复内容（仅 Rust 后端 + Cargo，前端零改动）

### 1. `project/src-tauri/Cargo.toml`
```toml
[dependencies]
tauri = { version = "2", features = [] }
tauri-plugin-single-instance = "2"   # 新增：桌面单实例护栏
```

### 2. `project/src-tauri/src/lib.rs`
- 引入 `use tauri::Manager;`（调用窗口管理 API 所需 trait）。
- 在 `tauri::Builder` 链上注册插件，第二个实例启动时遍历所有 webview 窗口并提到前台：
```rust
tauri::Builder::default()
    // 桌面单实例护栏：第二次启动聚焦已有窗口，禁止多开
    .plugin(tauri_plugin_single_instance::init(|app, _argv, _cwd| {
        for (_label, window) in app.webview_windows() {
            let _ = window.unminimize();
            let _ = window.show();
            let _ = window.set_focus();
        }
    }))
    .setup(|_app| { touchpoints::init(); Ok(()) })
    ...
```
- 设计取舍：遍历 `app.webview_windows()` 而非硬编码 label `"main"`，对单窗口/未来多窗口都稳健。

### 3. `capabilities/default.json`
- **无需改动**：`tauri-plugin-single-instance` 是纯 Rust 后端钩子，不暴露前端 JS 命令，不消耗 capability 权限。

### 行为级真机验证 — 边界说明（重要，不伪造）
- **沙箱 web 模式无法双开 Tauri exe 进程**，因此「第二次启动 → 聚焦已有窗口而非新建」这一跨进程行为**无法在 web 沙箱真机验证**。
- 该行为只能在本地真实运行时确认：
  - 方式一：本地 `npm run tauri:dev`（或打包后双击 exe）启动一个实例，再启动第二个，确认第二个不新建窗口、而是把第一个提到前台（含从最小化恢复）。
  - 方式二：`tauri build` 出 `heartflow.exe`，连续双击两次图标，第二次应聚焦已开窗口。
- 这与「A/B 用独立 Edge + CDP 在 vite :1001 做真机取证」不同——single-instance 是 Tauri 原生进程级行为，web 等价层没有对应物，故未做行为级截图/取证，避免自圆其说。
