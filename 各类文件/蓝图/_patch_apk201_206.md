## 2.201 AI文档生成与就地写作增强（Notion AI → 思绪书房/字镜阁/输出管理）

### 核心设计理念
Notion AI 的核心不是「对话式问答」，而是「就地生成」：AI 能力以编辑器内嵌功能的形式存在，用户正在写什么，AI 就基于这段上下文续写、扩写、总结、改语气或生成大纲与表格，无需切换到独立对话框。其价值在于把「生成」与「创作流」合二为一——输入不中断，产出直接落进文档结构。
对心流工坊而言，思绪书房是私人写作空间，字镜阁承担文字打磨，输出管理负责成品导出。借鉴点在于：所有 AI 写作增强都以「当前文本上下文」为唯一依据，生成结果先以草案形式呈现、经用户确认后才写入，全程本地执行，创作主权始终在用户手中。

### 关键数据模型
```json
{
  "ai_document": {
    "id": "uuid",
    "title": "string",
    "blocks": [
      { "type": "text | outline | table | todo | quote", "content": "string", "order": "integer" }
    ],
    "context": {
      "source_notes": ["uuid"],
      "related_days": ["ISO8601"],
      "mood_refs": ["uuid"]
    },
    "local_path": "string",
    "created_at": "ISO8601",
    "updated_at": "ISO8601"
  },
  "generation_log": {
    "id": "uuid",
    "document_id": "uuid",
    "operation": "continue | expand | summarize | rewrite | outline | table",
    "context_excerpt": "string",
    "prompt": "string",
    "output_draft": "string",
    "accepted": "boolean",
    "created_at": "ISO8601"
  }
}
```

### 交互规格
**就地续写流程**：思绪书房「AI续写」→基于当前光标前的文本续写→生成草案以虚影样式呈现→用户确认后写入正文→草案不入库仅保留最终版。
**大纲生成流程**：思绪书房「生成大纲」→对整篇草稿提炼结构化大纲→大纲按章节插入文档顶部→用户可拖拽调整后自动重组正文顺序。
**文本改写流程**：字镜阁「改写润色」→选中段落选择风格（更凝练/更温暖/更正式）→生成改写对比稿→原稿与改稿并排对比→用户选定版本写入。
**总结提炼流程**：思绪书房「一键总结」→长文压缩为核心要点→要点以卡片形式存入经略阁→原文与要点双向链接。
**写作素材关联流程**：思绪书房「素材关联」→写作时自动检索本地笔记与逐日心锚条目→侧栏呈现相关素材→一键引用插入文档→引用带来源溯源。

### 心流工坊借鉴映射
| 借鉴要素 | 心流工坊落地 | 模块 |
|---------|------------|------|
| 就地生成（上下文内调用） | 思绪书房「AI续写/生成大纲」 | 思绪书房 |
| 草案确认制 | 生成结果一律以草案呈现、确认后才写入 | 思绪书房 |
| 文本改写与风格调整 | 字镜阁「改写润色」对比稿 | 字镜阁 |
| 总结提炼与要点沉淀 | 要点卡片入库经略阁并双向链接 | 经略阁 |
| 文档结构化（块体系） | 思绪书房块式文档 + 输出管理导出 | 输出管理 |

### 宪法合规确认
- ✅ 所有文档与生成记录存储在本地
- ✅ 无社交功能
- ✅ 用户主动触发
- ✅ 无云端依赖

## 2.202 稍后阅读与网页收藏（Pocket → 书签与入口架/释光阁/阅览殿）

### 核心设计理念
稍后阅读类产品的核心是「捕获与排空」双通道：看到值得读的内容时以极低成本一键暂存（捕获），之后在安静、纯净的阅读环境中集中消化（排空），阅读中的高亮与笔记沉淀为个人资产。Pocket 证明了一个朴素规律——收藏动作越轻，收藏率越高；阅读环境越纯净，读完率越高。
心流工坊的落地遵循同一逻辑：书签与入口架负责零负担的暂存入口，阅览殿提供无干扰的沉浸阅读，释光阁承接阅读中产生的高亮与批注。收藏、阅读、沉淀三者各归其位，形成「先收后读、读而留痕」的完整闭环，且全文以本地快照保存，链接失效也不影响阅读。

### 关键数据模型
```json
{
  "saved_item": {
    "id": "uuid",
    "url": "string",
    "title": "string",
    "content_snapshot": {
      "local_path": "string",
      "content_hash": "string",
      "captured_at": "ISO8601"
    },
    "status": "inbox | reading | archived | discarded",
    "tags": ["string"],
    "reading_time": "integer",
    "added_at": "ISO8601",
    "read_at": "ISO8601"
  },
  "highlight": {
    "id": "uuid",
    "item_id": "uuid",
    "text": "string",
    "note": "string",
    "color": "string",
    "linked_note_id": "uuid",
    "created_at": "ISO8601"
  }
}
```

### 交互规格
**一键收藏流程**：书签与入口架「稍后阅读」→网页正文抓取为本地快照→自动提取标题与摘要→入「待读箱」→标记为未读。
**沉浸阅读流程**：阅览殿「待读清单」→纯净排版无广告无干扰→阅读进度自动记录→中途退出下次续读。
**高亮沉淀流程**：阅览殿「高亮批注」→选中文字高亮并添加批注→长按高亮一键转存为笔记草稿→草稿进入思绪书房并可后续加工。
**排空归档流程**：书签与入口架「清空待读」→读完条目标记归档→高亮与批注汇入释光阁→定期回顾归档摘要→久未阅读条目提醒清理。

### 心流工坊借鉴映射
| 借鉴要素 | 心流工坊落地 | 模块 |
|---------|------------|------|
| 一键捕获暂存 | 书签与入口架「稍后阅读」待读箱 | 书签与入口架 |
| 纯净阅读环境 | 阅览殿「待读清单」沉浸排版与续读 | 阅览殿 |
| 高亮与批注沉淀 | 高亮转笔记草稿，加工后入思绪书房 | 思绪书房 |
| 收藏资产化 | 归档条目与高亮汇入释光阁长期检索 | 释光阁 |
| 待读清理提醒 | 久未阅读条目定期提醒，防收藏积压 | 书签与入口架 |

### 宪法合规确认
- ✅ 所有收藏内容与高亮存储在本地
- ✅ 无社交功能
- ✅ 用户主动触发
- ✅ 无云端依赖

## 2.203 语音转文字笔记（讯飞听见 → 镜我/思绪书房/更漏）

### 核心设计理念
语音输入比打字快数倍，讯飞听见验证了「想到即说、说完即成文」的可行性：方言与口音识别、自动标点、说话人分离，使语音到文字的转化接近零门槛。其核心价值不是「转写准确率」，而是把捕捉想法的时间成本降到最低——灵感来临时不因打字慢而流失。
心流工坊落地为三条通路：镜我承担口述日记与自我对话（说话人即自己，转写即心迹），思绪书房承接语音草稿的整理加工（语音转出的初稿进入写作流程），更漏负责语音待办与零碎提醒（一句话说出口即成为任务）。所有音频与转写文本均存本地，转写离线可用。

### 关键数据模型
```json
{
  "voice_note": {
    "id": "uuid",
    "audio_path": "string",
    "duration": "integer",
    "transcript": {
      "full_text": "string",
      "segments": [
        { "start_ms": "integer", "end_ms": "integer", "speaker": "string", "text": "string" }
      ],
      "status": "draft | reviewed | finalized"
    },
    "target": "diary | note | todo | memo",
    "linked_ids": ["uuid"],
    "created_at": "ISO8601"
  },
  "speech_todo": {
    "id": "uuid",
    "voice_note_id": "uuid",
    "text": "string",
    "due": "ISO8601",
    "priority": "low | medium | high",
    "done": "boolean"
  }
}
```

### 交互规格
**口述日记流程**：镜我「语音日记」→对着镜我说出今日心迹→自动转写并分段→转写稿归入当日逐日心锚→可回放原声对照。
**语音速记流程**：思绪书房「语音草稿」→口述想法自动转写→转写稿以草稿卡片入写作流→后续编辑成文→原音频随稿保存。
**语音待办流程**：更漏「说出待办」→一句话口述任务→自动转写并解析时间与优先级→生成待办条目→到期提醒。
**转写校对流程**：字镜阁「转写校对」→转写文本与音频逐段对照→点击段落即定位原声→修正错字→校对后状态置为已确认。

### 心流工坊借鉴映射
| 借鉴要素 | 心流工坊落地 | 模块 |
|---------|------------|------|
| 口述即记录 | 镜我「语音日记」转写归入逐日心锚 | 镜我 |
| 语音转写草稿 | 思绪书房「语音草稿」进入写作流 | 思绪书房 |
| 一句话任务化 | 更漏「说出待办」转写并解析时间 | 更漏 |
| 音频文本对照校对 | 字镜阁「转写校对」逐段定位原声 | 字镜阁 |
| 说话人分离（自我对话场景） | 镜我分身对话时区分「我/镜中我」声道 | 镜我 |

## 2.204 会议纪要转写（飞书妙记 → 更漏/释光阁/思绪书房）

### 核心设计理念
飞书妙记将「开会」与「记录」解耦：录音自动转写、说话人区分、时间戳定位，会后自动生成结构化纪要（议题/结论/待办），行动项可一键认领。其价值在于让会议产出可回溯、可执行——任何一句发言都能点回原声，任何一条结论都有据可查。
心流工坊将此能力内化为「与自己和他人的协作痕迹管理」：更漏承接行动项的提取与到期跟进，释光阁承接纪要的长期沉淀与检索，思绪书房承接由纪要引申出的思考与决策记录。纪要全文、音频与时间戳均本地保存，隐私不外泄，这正是本地优先生活记录工具的独特优势。

**行动项提取流程**：更漏「待办提取」→AI从转写中识别行动项与责任人→逐条确认后转为更漏待办→到期自动提醒。

**纪要检索流程**：释光阁「全文检索」→跨纪要搜索关键词→结果按相关度排列→点击跳转原文位置→关联到思绪书房决策笔记。

## 2.205 本地知识库AI问答（AnythingLLM → 经略阁/殿堂辞典/镜我）

### 核心设计理念
AnythingLLM 代表的「本地知识库问答」形态（RAG 检索增强生成）与通用聊天有本质区别：回答不是凭空生成，而是先从用户自己的资料库中检索相关内容，再基于检索结果作答，并标注答案出处。知识来自自己的积累、答案可溯源、数据不出本地，这是个人知识工具最稳妥的 AI 形态。
心流工坊三处落地：经略阁对本地笔记与资料做检索问答（我的资料我问答），殿堂辞典对概念词条做溯源释义（引证出处的解释），镜我用于个人岁月问答（如「去年我经历了什么」——基于逐日心锚与时间长廊数据作答）。一切检索与回答均在本机完成，无任何云端上传。

### 关键数据模型
```json
{
  "knowledge_source": {
    "id": "uuid",
    "type": "note | diary | article | dictionary | timeline",
    "title": "string",
    "local_path": "string",
    "content_hash": "string",
    "chunks": [
      { "index": "integer", "text": "string", "embedding_local": "vector" }
    ],
    "indexed_at": "ISO8601",
    "updated_at": "ISO8601"
  },
  "qa_session": {
    "id": "uuid",
    "query": "string",
    "answer": "string",
    "citations": [
      { "source_id": "uuid", "chunk_index": "integer", "excerpt": "string" }
    ],
    "scope": "vault | dictionary | personal_years",
    "created_at": "ISO8601"
  }
}
```

### 交互规格
**资料库问答流程**：经略阁「知识问答」→对本地全部笔记与资料提问→AI先检索后作答→答案附引用出处→点击引用直达原文段落。
**概念溯源释义流程**：殿堂辞典「溯源解释」→对词条提问→检索辞典与典籍本地库→答案引用多源出处→可展开查看原文上下文。
**个人岁月问答流程**：镜我「岁月问答」→提问关于自己的过去→检索逐日心锚、时间长廊与留光阁数据→答案以时间线方式呈现→点击年份回到当时记录。
**索引管理流程**：经略阁「本地索引」→新增笔记自动分块建索引→删除笔记同步清理索引→索引状态可视化→全部索引仅存本地。

### 心流工坊借鉴映射
| 借鉴要素 | 心流工坊落地 | 模块 |
|---------|------------|------|
| 检索增强生成（RAG） | 经略阁「知识问答」先检索后作答 | 经略阁 |
| 答案引用溯源 | 问答答案附出处，点击直达原文 | 经略阁 |
| 资料库本地索引 | 经略阁「本地索引」分块管理 | 经略阁 |
| 引证式概念解释 | 殿堂辞典「溯源解释」多源引用 | 殿堂辞典 |
| 基于个人数据的问答 | 镜我「岁月问答」检索个人时间线 | 镜我 |

## 2.206 图片文字识别与取词（白描 → 留光阁/字镜阁/释光阁）

### 核心设计理念
白描代表的轻量 OCR 形态价值在于「图片中的文字不再沉睡」：拍照即识别、截图即取词、表格还原、批量处理，纸面与图片里的内容第一次可以被搜索、被引用、被编辑。它解决的不是「识别率」问题，而是「文字被困在图片里」的信息孤岛问题。
心流工坊三处落地各有侧重：留光阁让照片中的文字可检索（照片记忆文字化），字镜阁承接识别文本的校正与再利用（识别结果变可用文本），释光阁承接票据、证书、资料页的归档（纸质资料数字化入阁）。识别全程离线进行，图片与文本均留本地，与 2.120 的「文档扫描归档」侧重互补：彼重扫描归档，此重文字提取与再利用。

### 关键数据模型
```json
{
  "ocr_task": {
    "id": "uuid",
    "image_path": "string",
    "source": "camera | screenshot | album",
    "mode": "text | table | batch",
    "status": "pending | recognizing | done | failed",
    "created_at": "ISO8601"
  },
  "ocr_result": {
    "id": "uuid",
    "task_id": "uuid",
    "text": "string",
    "blocks": [
      { "box": { "x": "number", "y": "number", "w": "number", "h": "number" }, "text": "string", "confidence": "number" }
    ],
    "recognized_lang": "string",
    "corrected": "boolean",
    "target": "photo_tag | note_draft | archive",
    "linked_ids": ["uuid"],
    "created_at": "ISO8601"
  }
}
```

### 交互规格
**拍照取词流程**：字镜阁「拍照识别」→对准纸面拍照→识别文字即时呈现→逐行校对修正→确认后转为文本存入思绪书房。
**截图文字提取流程**：留光阁「截图识别」→从截图提取文字→自动生成图片标签与描述→此后该图可被文字检索。
**表格识别流程**：字镜阁「表格还原」→拍摄或导入表格图片→识别并还原为表格结构→可编辑校对→转为本地表格文件。
**批量识别归档流程**：释光阁「批量归档」→勾选多张票据或证书图片→批量识别→文字与图片一并归档入阁→按内容分类检索。
