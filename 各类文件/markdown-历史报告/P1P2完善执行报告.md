## 五、完善-4：双笔记系统收敛（高风险）

### 5.1 风险根因
- `study`（思绪书房）与 `note`（便签）各自维护独立的 `notes` ref，却都通过 `storage.setNotes()` 全量覆写**同一个**全局笔记数组。
- 同一会话中二者先后新增笔记时，后写方会用自身数组覆盖全局数组，导致先写方的笔记丢失（双写覆盖隐患）。
- `Note` 类型两处均 re-export 自 `src/types`（同一来源，类型兼容）；`StickyNote.id === Note.id`，共享数组安全。

### 5.2 收敛方案
新增中性共享状态模块 `src/engine/storage/notes-state.ts`：

```ts
import { ref } from 'vue'
import { storage } from '../../engine/storage'   // 与 note/index、study/index 同款相对路径
import type { Note } from '../../types'

const notes = ref<Note[]>([])            // 全局笔记唯一引用源
export function loadNotesState()  { notes.value = storage.getNotes() }
export function persistNotesState() { storage.setNotes(notes.value) }
export function resetNotesState()  { notes.value = [] }  // 测试隔离用
export { notes }
loadNotesState()  // 模块初始化时加载一次
```

- `study/index.ts`：移除本地 `notes` ref 与 `loadNotes()/saveNotes()`，改为 `import { notes, loadNotesState, persistNotesState }`，`load()` 调 `loadNotesState()`，`persist()` 调 `persistNotesState()`。
- `note/index.ts`：移除本地 `notes` ref 与 `loadNotes()/saveNotes()`，全部 6 处 `saveNotes()` → `persistNotesState()`；`create` 将基础 `note` 推入共享 `notes.value`。
- **关键修复（见 5.3）**：`notes-state` 的 storage 导入使用 `'../../engine/storage'`（与 `note/index`、`study/index` 完全一致的相对路径），确保既有 `vi.mock('../../../engine/storage')` / `vi.mock('../../engine/storage')` 全部覆盖本模块导入，避免命中真实 storage（localStorage）。

### 5.3 测试隔离故障排查（重要经验）
- 初版 `notes-state.ts` 以 `'./index'` 导入 storage，导致 `note/__tests__/index.test.ts` 全量运行 11 例失败（跨用例污染：`archivedNotes` 期望 1 得 2、`deletedNotes` 期望 1 得 3）。
- 经逐层埋点确认：`notes-state` 为模块级单例，在 `vi.resetModules()` 下被复用；其 `storage.getNotes` 经探测 `isMock=false` —— 即 `'./index'` 这一相对路径**未被**测试中的 `vi.mock('../../../engine/storage')` 覆盖，于是 `loadNotesState()` 读的是真实 localStorage，而 `beforeEach` 只清空了 mock 的 `mockData.notes`，二者不是同一数组，笔记持续累积。
- 修复：将 `notes-state` 的导入改为 `'../../engine/storage'`（与既有 mock 注册路径同款解析），`getNotes isMock=true`，`beforeEach` 的清空如实生效，跨用例污染消除。
- 回归测试 `src/modules/study/__tests__/dual-note.test.ts`（3 例，验证 study/note 互不覆盖、共享同一引用）补充 `resetNotesState()` 进 `beforeEach`，并修正其 `invalidateCache` 导入来源（`engine/storage/core` 而非 `test-utils`）、`test-utils` 相对路径（三阶 `../../../`）。

### 5.4 结果
- `note/__tests__/index.test.ts`：28 通过
- `study/__tests__/dual-note.test.ts`：3 通过
- `study/__tests__/*` + `note/__tests__/*`：共 118 测试通过
