## 一、对话 A 收口纪实（P0 → P2）

### 1.1 P0 · 存储引擎修复
- **主存储回退为明文 JSON 文件**：贴合蓝图第一层"用户可直接查看编辑"。`project/frontend/src/engine/storage/core.ts` 的 `getBackend()` 在 Tauri 下返回 `PlaintextFileStorageBackend`（`cmd_save_storage`/`cmd_load_storage` 读写明文 JSON），web 下返回 `LocalStorageBackend`。
- **保留 `flush()`**：`save` 为同步缓存 + 异步挂起持久化，关闭前 `flushStorage()` 等待落盘，消除 fire-and-forget 丢数据风险；`main.ts` 注册 `beforeunload`/`pagehide`/`visibilitychange(hidden)` 钩子触发。
- **SQLite 降级为预留模块**：`sqlite-backend.ts` 不接入主路径，仅供蓝图第八层 L3 加密保险库（P2 第四阶段）预留。

### 1.2 P1 · 测试提速
- **根因**：Vitest4 移除了 `poolOptions`，旧配置静默失效，全量回归 15–20 min。
- **修正**：`vite.config.ts` 改为顶层 `pool:"threads"` + `maxThreads:16, minThreads:4`。
- **结果**：全量 **278 文件 / 6847 用例，全部通过，0 失败，~2.5 min**。
- 同时根治第二处跨午夜时区 bug（`p21-bond-bridge.test.ts` 用本地日期分量构造替代 `toISOString()`）。

### 1.3 P2 · 蓝图核心引擎缺口校正（5 项全落地）
| 项 | 内容 | 关键文件 |
|---|---|---|
| ① 感知层输入 | 纯前端环境/健康/设备采集，接入编排与氛围引擎，零后端 | `src/modules/perception/{types,usePerception}.ts`、`src/stores/perception.ts`、`App.vue`、`main.ts` |
| ② 运行时宪法中性检测 | 填 `say()` 空桩（forbiddenPatterns/comparativePhrases/personification），观测优先、不拦截 | `src/modules/constitution/neutrality-checker.ts`、`stores/advisor.ts` |

## 二、对话 B · 前端架构研判（潮流视角）

### 2.1 技术栈快照
- Vue 3.5.13 / Pinia 3.0.4 / vue-router 4.6.4 / Vite 6.0.3 / TS 5.6.2 / Vitest 4
- 状态：11 个 Pinia store（setup 写法）+ 80+ 领域 composable，**无 signals**
- 模块：80+ 模块经巨型 barrel `src/modules/index.ts`（432 行）暴露；插件子系统是**真实框架**（`loader/api/plugin-scheduler/sandbox`）
- 渲染：自研 `scene-renderer`（RAF + 三档性能档 + 拓扑排序 + 脏区域），Canvas2D / SVG / CSS，**无 WebGPU**
- AI：`AIProvider` 抽象 + SSE 流式 + Ollama 本地 + IPC 到 Rust；宪法规则 → `complianceOverride` 门控输出
- 数据：明文 JSON（Tauri）+ localStorage，`SCHEMA_VERSION=10` 逐步迁移，**无 zod 运行时校验**
- 类型：`strict` + `noUnusedLocals/Parameters`，**零运行时校验**

### 2.2 趋势对齐矩阵

**领先（ahead of curve）**
1. **本地优先 / 数据主权** — 明文 JSON 离线存储 + 迁移 + `data-sovereignty` 模块，领先云优先常态（缺 CRDT 合并，单设备桌面可接受）。
2. **宪法式 AI 治理** — 规则→`complianceOverride`→系统提示词 + 输出校验，是"constitutional AI"治理范式，在消费级应用中罕见且前卫。
3. **平静科技 / 心流设计** — 产品本体即反多巴胺引擎优化、重心流/氛围/感知，领先主流交互范式。

**对齐（on the curve）**
4. 插件化 / 沙箱分级架构（真实能力隔离框架，但三套体系并存）
5. Canvas2D 自研渲染管线（sophisticated，但非 GPU）
6. 流式 AI 抽象 + 本地推理（Ollama 为独立进程，非浏览器内 WebGPU）
7. 严格 TS（编译期安全到位，运行时缺失）

**滞后（behind frontier）**
8. 细粒度响应式 — 仍 Pinia store 级，未用 signals/nanostores 或 Vue Vapor mode
9. 运行时校验 — 全仓零 zod/valibot，存储与 AI 响应靠手写 try/catch
10. 构建工具链 — Vite 6 + `vue-tsc` 前置（慢），未上 Vite 7/Rolldown + oxc/oxlint
11. WebGPU 渲染 — 对"生成式心流视觉"而言，GPU 粒子/流体/着色器是前沿差异化点

**机会（已设计未接线）**
12. **AI 智能体化** — 插件能力 API（`data:read/write`、导航、通知）本质是 agent 工具面；若开放给 AI 形成 MCP 式工具调用闭环，即 2026 智能体前沿。当前 `resonance` 层与插件注册表均未真正接入 80+ 模块。

### 2.3 关键发现
- **护城河（不是跟风）**：本地优先 + 数据主权 + 宪法式 AI 治理 + 平静科技，四者叠加构成真正差异化。
- **可补工程债**：运行时校验缺失、构建链滞后、纯 Canvas2D——均不影响架构正确性。
- **架构熵（需警惕）**：
  ① `resonance/` 协议层孤立未接线；
  ② `sqlite-backend.ts` 游离未引用（按设计预留 L3 保险库，需明确或删）；
  ③ barrel `export` + `CustomEvent` pub/sub + 插件注册表三套组合模型并行，仅前两者生效；
  ④ 沙箱为逻辑隔离（tier 决定），非真实 VM/Worker 隔离，第三方社区插件场景下安全边界偏软。

## 三、功能扩充方法论（怎么加功能）

本仓库已具备 6 个清晰扩展点。新增功能 = 选对扩展点 + 套用如下配方。所有路径相对于 `project/frontend/src/`。

### 3.1 扩展点配方

**(1) 新增领域模块** — `modules/index.ts:431-432`
```
建 src/modules/<name>/{types.ts, <impl>.ts, index.ts}   // index.ts 只做重导出
// 在巨型 barrel 加两行：
export { useXxx, computeXxx } from './<name>'
export type { XxxInput, XxxResult } from './<name>'
```
模板参考 `src/modules/association/`（types+engine+index 三件套）。

**(2) 声明插件能力** — `modules/plugin/types.ts` + `modules/plugin/api.ts:9-46`
```ts
// PluginPermission: read:current|read:history|write:data|export:data|network|filesystem|read_sessions|read_notes
// PluginTier: 'official'|'community'|'experimental'
registerPluginAPI('data:read', { getSessions: () => storage.getSessions() })
registerPluginAPI('navigation', { navigate: (path) => window.dispatchEvent(new CustomEvent('hf:navigate',{detail:{path}})) })
// 权限校验：loader.ts:71-78 hasPluginPermission（official 全放行，community 校验 permissions）
```

**(3) 共鸣事件（类型化 pub/sub）** — `resonance/interaction.ts:64-82`
```ts
engine.on('tap', listener)        // InteractionEventType 联合：'tap'|'long-press'|'swipe-up'...
engine.off('tap', listener)
// 数据变更总线：data-transfer.ts:149-151 subscribe(domain, listener)/unsubscribe(domain, listener)
```

**(4) 新增幕僚** — `modules/advisor/presets.ts:15-142` + `types/advisor.ts:175-226`
```ts
// 在 DEFAULT_ADVISOR_PRESETS 数组追加一项
{ id:'preset-<key>', name:'…', role:'…', personality:'…', state:'dormant',
  affinity:0, level:1, totalInteractions:0, createdAt:Date.now(), lastActiveAt:0,
  unlocked:true, responsibilities:[…] }
// 约定：PRESET_ADVISOR_ID_PREFIX='preset-'，isPresetAdvisorId(id) 区分预设/自定义
```

**(5) 新增路由/视图** — `router/index.ts:30-35`
```ts
withRoomMeta({ path:'/xxx', name:'xxx', component:()=>import('../views/Xxx.vue'), meta:{title:'…'} })
// withRoomMeta() 自动注入 roomId；懒加载 = 动态 import()
```

**(6) 调用/扩展 AI** — `engine/ai/provider.ts:14-47` + `engine/ai/index.ts:317`
```ts
const aiEngine = new AIEngine()
await aiEngine.chat([{role:'system',content:…},{role:'user',content:…}])   // 通用调用
// 新增专属回复流：在 AIEngine 加 getXxxReply() 方法，复用 getAdvisorReply 模式
// 宪法门控：constitution-effect.ts 的 EFFECT_TO_OVERRIDE_MAP 把规则映射到 complianceOverride；
//          say() 在 advisor.ts:1176 静默拦截、:1202 调 checkAdvisorNeutrality()
```

### 3.2 通用加功能工作流
1. **定扩展点**：纯计算/数据 → 模块；要开放能力给插件/AI → 插件能力；交互信号 → 共鸣事件；对话主体 → 幕僚；独立页面 → 路由；智能回复 → AI 调用。
2. **建模块**：`types.ts`（纯类型）+ `<impl>.ts`（逻辑）+ `index.ts`（重导出），并补充 `__tests__/`。
3. **注册**：在 `modules/index.ts` barrel 加两行；若是能力则 `registerPluginAPI`；若是幕僚则进 `presets.ts`。
4. **接线**：用 Pinia store 作单一真源（如感知 `stores/perception.ts`），在 `App.vue`/`main.ts` 启动；跨模块用共鸣事件而非直接 import 副作用。
5. **守宪法**：任何 AI 输出经 `conplianceOverride` + `checkAdvisorNeutrality` 门控；记录严守"不存幕僚评价"原则。
6. **测试门禁**：Vitest 下新增测试，全量回归需保持绿（当前 6847 用例基线）。

## 四、优化路线图（回应"如何优化"）

| 优先级 | 优化项 | 成本 | 影响 | 具体动作 |
|---|---|---|---|---|
| **P0** | 运行时校验 | 低/中 | 高 | 在存储加载 + AI 响应边界落地 zod/valibot，让明文↔结构迁移更安全 |
| **P0** | 统一能力总线 | 低/中 | 高 | 以 `resonance` 或插件能力 API 为唯一总线，淘汰 `CustomEvent` 与巨型 barrel，消除三套并行 |
| **P1** | 构建链升级 | 中 | 高 | Vite 6→7（Rolldown，Rust 打包）+ oxc/oxlint 替 `vue-tsc` 前置 + `manualChunks` 分包 |
| **P1** | AI 工具化闭环 | 中 | 高 | 把插件能力 API 暴露为 AI 工具，形成"宪法门控 + 本地优先 + 智能体闭环" |
| **P2** | WebGPU 渲染 | 高 | 差异化 | 氛围/粒子/流体着色器管线，替代纯 Canvas2D |
| **P2** | Vapor + signals | 高 | 中 | Vue Vapor mode + 细粒度响应式热路径 |
| **P2** | 多端 CRDT 同步 | 高 | 中 | 把"本地优先"升级为"本地优先 + 可合并同步"（若规划移动/多设备） |

**合理保留的偏离**：定制 CSS + 设计令牌（非 Tailwind）对强氛围设计语言是正确选择；逻辑沙箱在可信插件场景可接受，仅第三方社区插件时需补强（真实 Worker/VM 隔离）。

## 五、MVP 功能候选项（回应"功能太少"）

基于现有架构缺口，以下候选功能**复用既有扩展点**、成本可控、能直接体现产品差异化：

1. **跨域关联可视化呈现**（复用 association 引擎，扩展点：视图+渲染）
   关联引擎已算但可能未 UI 呈现。新增 `/association` 路由 + 力导向图（Canvas2D 即可），展示"共标签/时间邻近/因果"三类链接。最低成本验证架构价值。

2. **习惯/专注会话记录与复盘**（扩展点：模块+存储+幕僚）
   心流本体天然需要"专注会话"实体：开始/结束/时长/心境标签 → 落明文 JSON → 经 association 与日记/笔记关联 → 守钟人幕僚做周期复盘。填补"记录→关联→复盘"闭环。

3. **数据主权：加密保险库接线**（扩展点：存储后端）
   把游离的 `sqlite-backend.ts` 接为 L3 加密保险库（用户口令派生密钥，敏感域如密码/私密日记存加密库，其余留明文）。既消除死代码，又兑现蓝图第八层。

4. **AI 智能体工具闭环（P1 前置）**（扩展点：插件能力 API + AI）
   将 `data:read/write`、导航、通知注册为 AI 可调用的工具，让幕僚能"读你的记录并帮你跳转/提醒"。这是 2026 智能体前沿，且本仓库能力面已现成。

5. **幕僚互动深化：低语（dingyin）成长线**（扩展点：AI + store）
   `getDingyinReply()` 已存在。增加 affinity 成长曲线可视化 + 解锁动画，让 6 预设幕僚从"存在"到"有生命力"。
