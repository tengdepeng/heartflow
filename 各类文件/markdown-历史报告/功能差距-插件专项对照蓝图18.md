## 四、⚠️ 「存了未消费」核验（本项目铁律）
- 插件 API 注册了核心能力（data:read/write、navigation、notification），并经 `resonance/bridges/plugin.ts` 桥接。
- 但 grep `getPluginAPI(...)` 直调：**仅在 `modules/plugin/__tests__/` 与 `loader.ts` 内部使用**，38 个功能房间/视图中**无一处直接消费插件能力**。
- 结论：插件「管理闭环」已闭合（符合蓝图18自评），但「被功能房间当作可调用能力消费」的生态尚未形成——插件目前是"能被安装/管理/展示"，尚未"被各房间调用扩展功能"。下一步应**先补真实消费**（让房间经 `getPluginAPI`/共振桥调用插件能力），再补生态外环（远程市场/社区）。

## 五、优先级建议（基于蓝图18 落地路线图 P4 生态/传承）
1. **先补真实消费**：挑 2–3 个房间（如镜我对话分身插件、思绪书房剪藏）经共鸣层消费插件 API，验证内核真被用（消除"存了未消费"）。
2. **再补生态外环**：远程市场分发 + 三级分级对外策展 + 权限逐项开关/撤销 UI（P2）。
3. **最后**：社区 P2P 分享 / 访客 / 世界互通 / 商业化 / 第三方 SDK（P3，属 P4 晚阶段）。
