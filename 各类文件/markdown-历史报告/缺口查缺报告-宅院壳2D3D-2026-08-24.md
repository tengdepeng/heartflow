# 宅院壳 2D/3D 缺口查缺报告

**日期**：2026-08-24
**验证方式**：真实浏览器级（独立 Edge `--app=http://127.0.0.1:1001 --remote-debugging-port=9222`，Blink 内核与 Tauri webview 同源等价），用 CDP `Input.dispatchMouseEvent` 真实派发拖拽/滚轮，配合 `elementFromPoint`、计算样式、命中元素事件投递日志与像素差分取证。
**被测入口**：`project/frontend/src/modules/world-shell/courtyard-3d.ts`、`courtyard.ts`，`CanvasRoom.vue`，`project/src-tauri/tauri.conf.json` / `Cargo.toml`。

---

## 一、真机证据

| 指标 | 3D 模式 | 2D 模式 |
|------|---------|---------|
| `.courtyard-3d-canvas` 存在 | 是 | 否（2D 无 3D canvas） |
| 3D canvas `pointer-events` | **`none`** | — |
| 3D canvas `z-index` | 3 | — |
| `.shell-hit-layer`（命中层）`pointer-events` | **`auto`** | — |
| 命中层 `z-index` | 5 | — |
| 屏幕中心 `elementFromPoint` 命中 | `.shell-hit-layer`(pe:auto) | `.river-empty`(pe:auto) |
| 真实拖拽+滚轮中命中 **3D canvas** 的事件数 | **0** | 0 |
| 事件实际落点 | `shell-hit-layer`（拖拽）、`mirror-self`（滚轮） | `river-empty`/`sidebar-overlay`（拖拽）、`mirror-self`（滚轮） |
| 结论 | **OrbitControls 被饿死** | 无相机，无拖拽/缩放 |

> 关于像素差分：3D 拖拽后 `afterDragDiffFrac≈0.40`，但 2D（根本无相机、无 OrbitControls）在**同一套拖拽+滚轮序列**下也出现 `≈0.42` 的同等差分。这证明该差分来自共享 UI 反应（滚轮命中玉珠 orb `mirror-self`、拖拽过程触及 `sidebar-overlay`/悬停高亮等），**并非 3D 相机旋转**。权威判定依据是「命中 3D canvas 的事件数 = 0」+「3D canvas 计算样式 `pointer-events:none`」。

## 二、用户两点诉求结论

### ① 拖拽方向 / 缩放大小等是否可自定义？
**结论：2D 无拖拽/缩放；3D 代码里配了但实质失效；且两者都没有任何面向用户的自定义入口。**

- **2D 宅院壳**（`courtyard.ts`）：纯静态剪影骨架（`drawSilhouette`/`drawAnchors` + `hitTest`），没有任何 OrbitControls、平移、缩放逻辑——设计如此，2D 本就不支持拖拽/缩放。
- **3D 宅院壳**（`courtyard-3d.ts`）：
  - 第 158 行 `new OrbitControls(camera, this.canvas)` 绑在自建 canvas 上；
  - 但第 118 行 `ownCanvas.style.pointerEvents = 'none'`，且该 canvas 由 `document.body.appendChild` 挂在 `z-index:3`；
  - 上方 `.shell-hit-layer`（`z:5`, `pointer-events:auto`）独占指针事件，且 `CanvasRoom.vue` 的 `onShellHit` 只处理 `click`（进房间），**从不转发拖拽/滚轮**；
  - 因此 OrbitControls 的 `rotateSpeed`/`zoomSpeed`/`enableDamping`/`minDistance`/`maxDistance` 全部配了却 **一个事件都收不到** → 3D 拖拽旋转 + 滚轮缩放**完全失效**（真机实证事件命中 3D canvas = 0）。
- **自定义入口**：前端仅持久化 `courtyardLayout`（三进门/一门/环形）与 `fogDensity`（雾浓度）。`rotateSpeed`/`zoomSpeed`/拖拽方向/缩放范围均为**硬编码常量**，设置面板里没有任何调节项。宪法约束（外观/3D 参数本地保存不写死）在此处未被满足——rotateSpeed/zoomSpeed 写死、且无 UI。

### ② 是否禁止打开多个窗口？
**结论：桌面端未禁止。双击 exe 可开多个独立窗口。**

- `project/src-tauri/tauri.conf.json`：仅定义一个窗口（`1100×720`, `resizable:true`, 非全屏），**无任何 single-instance 配置**。
- `project/src-tauri/Cargo.toml`：`tauri = { version="2", features=[] }`，**未引入 `tauri-plugin-single-instance`**。
- `project/src-tauri/src`：无任何 `single_instance` / `WindowBuilder` / `create_window` / 多窗口代码。
- → 每次启动（双击 exe 或从 shell 拉起）都会新建一个独立实例，多窗口并存，数据各自独立（localStorage/明文 JSON 文件按实例隔离，存在数据分叉风险）。

---

## 三、根因

1. **3D 交互断链**：为修复「3D 被遮挡看不见」而让自建 canvas `pointer-events:none` + 命中层接管点击，却把 OrbitControls 绑在这个 `pe:none` 的 canvas 上——拖拽/滚轮由此被一并切断，只剩「点进房间」的 click 透传。属于上一轮「让 3D 看得见」修复的连带副作用。
2. **缺单实例护栏**：Tauri2 单实例需显式装 `tauri-plugin-single-instance` 并在 `tauri.conf.json`/Rust 入口登记，本仓库从未接入。

---

## 四、可选修复方案（待拍板）

**A. 修复 3D 拖拽/缩放（让 OrbitControls 真正收事件）**
- A1（推荐·最小改动）：命中层在「按下并移动」时把 drag/wheel 转发给相机。即 `onShellHit` 增加 `pointerdown/move/up` + `wheel` 监听：拖拽时临时让 3D canvas `pointer-events:auto`（或直接把事件 `dispatch` 到 canvas），松手后回落 `none`；滚轮同理。保留「空白点击进房间」语义。
- A2：让 3D canvas 常态 `pointer-events:auto`，命中层只在「非拖拽的纯 click」时插手（pointerdown 时判断是否会形成拖拽，未拖动才透传 click）。
- A3：把 OrbitControls 的事件源从 canvas 改为 `document` 或命中层容器，由 `onShellHit` 统一分发 click/drag/wheel。

**B. 加 3D 自定义入口（满足宪法「不写死」）**
- 在设置面板暴露 `rotateSpeed`/`zoomSpeed`/拖拽方向（轨道 vs 第一人称环视）/缩放范围，落盘进 `config.worldShell.shellConfig`，`courtyard-3d.ts` 的 `updateContext` 已具备接收 `intensity`/`sanctuary`/`config` 的通道，可顺势消费。

**C. 桌面单实例护栏**
- 安装 `tauri-plugin-single-instance`，`tauri.conf.json` 登记插件，`lib.rs`/`main.rs` 注册；已有实例收到第二次启动的 `on_arguments` 时聚焦窗口（并可选把深链参数转交当前窗口）。移动端本就不支持多窗口，无需改动。
