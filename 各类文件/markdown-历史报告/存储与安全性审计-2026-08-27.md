## 一、执行摘要

| 维度 | 结论 |
|---|---|
| 主存储引擎 | 单一整库 `StorageSchema`，Tauri 下明文 JSON 文件（`cmd_save_storage`），Web 下 localStorage（`heartflow:storage`） |
| 加密能力 | **已有两套**：B0 整库信封加密（AES-GCM-256，口令+设备双密文，可选默认关）+ 保险库独立强加密（PBKDF2 150k + AES-GCM-256） |
| 明文隐私 | 默认关闭加密 → 整库明文落盘，任意能读文件者可直接看全部内容（含笔记/情绪/账本）。符合宪法「用户可查看编辑」，但默认无保密 |
| 自动锁定 | 保险库空闲/切页自动锁定已实现（`useVaultAutoLock`），锁定的是保险库 UI 而非整库 |
| **真实风险** | ① 安全备份恢复 `backup-recovery.ts` 用**裸 `localStorage`** 而非 `storage.setKV`，Tauri 桌面端持久化存疑；② 安全备份**明文**未加密（对照 `*.vault` 是加密的） |

## 二、存储架构总览（三层 + KV 子层）

```
┌─ 整库 StorageSchema（saveSchema/loadSchema）
│   ├─ Tauri  → PlaintextFileStorageBackend（明文 JSON 文件，单一文件，用户可看可改）
│   └─ Web    → LocalStorageBackend（localStorage key=heartflow:storage）
│   └─ 装饰层 → EncryptedStorageBackend（可选启用：整库 AES-GCM-256 双密文信封）
├─ KV 子层（storage.getKV/setKV → schema.kvStore）
│   各功能局部状态统一汇入 kvStore，随整库一起落盘/加密
└─ 独立加密（不进整库明文）
    └─ 保险库 vault.ts（VAULT_CIPHER_KEY 存 kvStore，值为 AES-GCM-256 密文）
    └─ 保险库导出 *.vault（encryptWithPassphrase 加密文件）
```

**版本迁移**：`migrate()` 属性级合并 + `ensureConfigDefaults()` 补齐嵌套字段（含 `complianceOverride.allowExternalAI` 等 fail-closed 默认），幂等安全。

## 四、安全性评估

### 4.1 加密能力（已实现，默认关）
- **B0 整库信封加密**（`EncryptedStorageBackend`）：AES-GCM-256，双密文（primary=口令 PBKDF2 派生，device=本机设备密钥兜底防口令丢失锁死）。`enableEncryption/disableEncryption/unlockWithPassphrase/unlockWithDevice/changePassphrase` 完整编排。
- **保险库独立加密**（`vault-cipher.ts`）：PBKDF2(SHA-256, 150,000 迭代) + AES-GCM-256，密钥仅存内存，密文+盐+IV 落盘。口令错即 `VaultDecryptError`。
- **设备密钥**（`device-secret.ts`）：Tauri 走 `cmd_get_device_secret`（Rust 端本机持久化 secret），Web 退化。
- 评价：加密基建成熟，强度达标（行业标准 AES-GCM-256 + 高迭代 PBKDF2）。**短板是默认不启用**——开箱即明文，用户需主动开启整库加密；保险库则需用户设口令才加密。

### 4.2 自动锁定
- `useVaultAutoLock`：空闲计时（默认 5 分钟）+ 页面可见性监听（切页即锁），锁的是保险库 UI 遮罩，非整库。本地实现，无外部调用。✅ 符合宪法本地私有。

### 4.3 备份恢复（有缺陷，见风险）
- 保险库备份 `*.vault`：加密导出，✅ 安全。
- 全局安全备份 `backup-recovery.ts`：**裸 localStorage 明文**写 `hf:backup_*`，❌ 见风险 ① ②。

### 4.4 Tauri vs Web 差异
- Tauri：整库明文 JSON 文件（用户文件可查看编辑，符合蓝图第一层）。Web：localStorage。
- **关键坑**：`backup-recovery.ts` 直接 `localStorage.setItem`，在 Tauri 下 webview 的 localStorage 是沙箱存储，**不随整库 JSON 文件落盘**，桌面端备份可能不持久/位置不可控。

### 4.5 明文隐私风险
- 默认不加密 → 文件/浏览器存储可被直接读取。敏感数据（笔记、情绪、账本、相册 base64、注意力行为）全明文。符合宪法「用户可编辑」，但默认无保密层。
- 建议：默认开启整库加密或至少在首次启动引导用户设口令（保险库已强制口令，整库可不强制但提供一键启用）。

### 4.6 越权 / 注入面
- 存储为本地单用户，无多用户越权面。
- JSON.parse 均有 try/catch 兜底，无原型污染（用 `Object.assign`/结构化克隆而非 `__proto__` 赋值）。
- 无 SQL（SQLite 后端未接入主路径，仅预留蓝图第八层）；KV 走 Rust 命令参数化。注入面低。

## 五、风险清单

| 级别 | 风险 | 位置 | 影响 | 建议 |
|---|---|---|---|---|
| **P1** | 安全备份用裸 `localStorage` 而非 `storage.setKV` | `modules/safety/backup-recovery.ts:224/230/265/307/314/329` | Tauri 桌面端备份不持久（沙箱 localStorage）；且备份明文含敏感数据 | 改为 `storage.setKV` 入整库，或 Tauri 下 `invoke('cmd_save_storage')` 写文件；备份体加密 |
| **P1** | 安全备份明文未加密 | 同上：`JSON.stringify({metadata, data})` 裸存 | 备份泄露=全量明文 | 复用 `vault-cipher` 加密备份载荷 |
| **P2** | 整库默认不加密 | `core.ts`（EncryptedStorageBackend 默认未启用） | 开箱明文 | 首次启动引导启用整库加密（不强制，守宪法第2条超级自定义） |
| **P2** | 相册 base64 入 kvStore | `anchor/photo-diary.ts` | 大图撑大整库 JSON，影响读写性能 | 大图考虑独立文件 + 索引（蓝图 MarkDown 分文件方向） |
| **P3** | 设备密钥 Web 退化 | `device-secret.ts` | Web 模式无 Rust 设备密钥，兜底解锁弱 | 已知限制，文档标注即可 |

---

## 六、建议（按优先级）

1. **修 P1**：`backup-recovery.ts` 改用 `storage.setKV`（或 Tauri 文件命令），并对备份载荷加密（复用 `vault-cipher`）。这是唯一阻断级缺陷。
2. **做 P2**：首次启动引导整库加密一键启用（fail-closed 默认，守宪法）。
3. **监控 P2**：相册大图单独处理，避免整库 JSON 膨胀。
4. 其余模块存储模式健康，无需改动。

## 结论

存储架构健康、加密基建成熟（两套 AES-GCM-256）。**唯一真缺陷是全局安全备份恢复混用了裸 localStorage 且明文**——在 Tauri 桌面端既可能不持久、又泄露敏感数据。建议优先修 P1，其余功能落点清晰、安全性达标。
