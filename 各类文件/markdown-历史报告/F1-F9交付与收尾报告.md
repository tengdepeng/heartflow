## 6. 已知限制

1. **OS 通知门控未统一（关键）**：`isOsNotificationBlocked()` 目前仅在 `modules/touchpoints/push-channel.ts` 内被调用。以下 3 处直接调用 OS `Notification` API 且**不**受 `complianceOverride.notificationBlocked` 约束：
   - `src/composables/useDesktopTouchpoints.ts`（桌面通知 composable）
   - `src/engine/automation.ts`（自动化触发通知）
   - `src/modules/rest/notification-bridge.ts`（`useRestNotificationBridge` 休息提醒）
   
   后果：用户若在宪法中将「无推送」置为关闭（notificationBlocked=true），上述 3 条路径仍可能弹出 OS 通知，第5条并非端到端 fail-closed。
2. **F4/F7 新子特性无独立断言**：四束光、呼吸跟随仅受组件级渲染测试覆盖，未对新增交互/状态单独断言。
3. **第43–45条正文为合成**：蓝图未给出逐条精确表述，本次依据「价值观红线」与「场景隐私」合成本簇（分享本地边界 / 禁打扰红线 / 禁攀比红线），需用户审阅并回写精确蓝图表述。
4. **宪法 effect 软效果仍非全部运行时消费**：差距报告 P1①（让 `constitution-effect.ts` 的 `EffectTarget` 真正被运行时消费，把「无推送/中性呈现/安全岛静默」做成硬门控）本次聚焦「建模条款」而非「接线生效」，属后续项。
