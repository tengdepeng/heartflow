## 1. 架构总览

沿用项目既有分层契约 **「薄委托层 + 模块内 composable 持有状态」**：

```
房间视图 (views/*.vue)             ← 挂载面板、持有局部 handler
   │  <XxxPanel />
   ▼
薄面板组件 (components/*.vue)       ← 仅展示 + emit 事件，无业务状态
   │  import composable from modules/*
   ▼
模块 composable (modules/*/*.ts)    ← 持有 reactive 状态 + 读写 storage
   │
   ▼
存储引擎 (engine/storage)          ← 明文 JSON 文件（本地私有，零网络）
```

**关键约定**（与项目记忆铁律一致）：
- 面板 `.vue` 是薄委托层，**不**持有业务状态；状态与存储逻辑在 `modules/*` 的 composable。
- 判"缺失/空壳"前先 `grep` 实现层——只读 `.vue` 会误判（见 PRD R-1）。
- 公共 API 经模块 `index.ts` 集中导出，避免散落 import。

## 3. 数据流

以保险库自动锁为例：

```
Vault.vue
  ├─ useVaultAutoLock() ──▶ autoLockSettings (reactive, 来自 AUTO_LOCK_KEY)
  ├─ <VaultAutoLockPanel :settings="autoLockSettings" @update="handleAutoLockUpdate" />
  │        │ 用户改时长
  │        ▼ emit('update', newSettings)
  └─ handleAutoLockUpdate(s) ──▶ useVaultAutoLock().save(s) ──▶ storage.set(AUTO_LOCK_KEY, s)
                                                                      │
                                              重载后 useVaultAutoLock() 读 AUTO_LOCK_KEY 恢复
```

心智地图类似：`MindMapPanel` 调 `useMindMap()` 读笔记 → `generateFromNotes()` 建图 → 写 `MIND_MAP_STORAGE_KEYS`。

## 4. 接线约定

- 视图在 `<template>` 直接挂载 `<XxxPanel />`，composable 从 `modules/*` 导入（不跨层 import 内部文件）。
- 面板 props 单向流入（`settings`），变更经 `emit('update')` 上浮到视图 handler 落库——**状态归属模块，视图只做编排**。
- `StewardPanel` 用 `v-if="showSteward"` + `Transition` 控制显隐，固定层 + 受控 `z-index`，遵循空间容器布局契约，不压导航 chrome。

## 6. 与项目契约对齐

- **薄委托层契约**：面板无业务状态，状态在 composable（满足，已 grep 核实）。
- **判缺失前 grep 实现层**：PRD R-1 已落实——避免把真实消费误判为空壳。
- **宪法硬约束**：零网络（明文 JSON 本地）、偏好本地保存（自动锁 `AUTO_LOCK_KEY`）。
- **存储引擎**：沿用 `engine/storage` 明文 JSON 主路径，未引入 SQLite 后端。
- **不引入接线孤儿**：面板均被真实房间视图消费，无悬空组件（死文件 `components/Astrolabe.vue` 已在 `9fc1069` 清理，与本次无关）。
