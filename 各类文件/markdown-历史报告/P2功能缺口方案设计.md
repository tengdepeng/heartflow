## ADR-M1：把现有可视化子系统上盘（接线而非重建）

### Status
**Done (verified 2026-08-16)** —— `views/VisualizationStudio.vue` 已建、路由/room-graph 已注册、本地数据适配器已落地、四道闸门验证（M1 相关文件全绿）。

### Context
`modules/visualization/` 已是一个完整子系统：
- `dimension-mapping/seven-dimensions.ts`：1545 行。`SevenDimensionEngine` 七维映射（数据源过滤/形状原子/大小/颜色/关系/时间/交互）+ 中文自然语言解析 `parseNaturalLanguage`（"用光弧表示每个应用，使用时长决定长度…"→ 配置）。
- `canvas-renderer.ts`：`useCanvasRenderer()` Canvas 2D 渲染管线（图层/脏区/帧调度）。
- `datasource-connector.ts`：`useDataSourceConnector()` + `useTransformPipeline()`（过滤/排序/聚合/分组/分页）。
- `dashboard-layout.ts`：`useDashboardLayout()` 仪表盘网格布局。
- `chart-interaction.ts`：`useChartInteraction()` 缩放/平移/标注/导出/响应式断点。
- ⚠️ **更正**：不存在独立的 `visualization-bridge.ts`。`modules/visualization/index.ts` barrel 已将上述子模块统一导出（含 `SevenDimensionEngine` / `createSevenDimensionEngine` / `parseNaturalLanguage` / `nlpConfigToSevenDimensionConfig` / `useCanvasRenderer` / `useDataSourceConnector` / `useDashboardLayout` / `useChartInteraction` / metaphors / style-packs）。M1 直接消费该 barrel，无需另建 bridge。
- 测试：`seven-dimensions.test.ts`、`__tests__/p16-visualization.test.ts`（覆盖引擎/渲染/数据/布局）。

**问题**：除 `metaphors` 被 `views/MaterialWorkshop.vue` 引用外，整条管线 + bridge **无任何视图消费**——是"建好没通电"的孤儿。

### Decision（已落地）
建 `views/VisualizationStudio.vue`（路由 `/visualization-studio`，room-graph 节点 `visualization-studio`），消费 `modules/visualization` barrel（直连 `SevenDimensionEngine` + `useCanvasRenderer` + `parseNaturalLanguage`/`nlpConfigToSevenDimensionConfig`），把"七维引擎 + Canvas 渲染 + 本地数据源 + 自然语言入口"串成可用面：
1. **数据源接真实本地数据（架构更正）**：⚠️ **不经由 `useDataSourceConnector`**。该连接器面向网络/REST/WebSocket，其核心 `fetchData()` 走 `window.fetch(url)`，与宪法第1条「本地私有、数据绝不离开本设备」直接冲突。`storage` 已是纯本地 KV 读取 API，故新建本地适配器 `modules/visualization/studio-data.ts`：直接消费 `storage.getSessions/getNotes/getEmotions/getAnchors` 并映射为 `SevenDimensionDataItem[]`（见下方 IO 契约），再喂给引擎。若未来确有外部数据源需求，再经合规网关接入，不在本模块内。
2. **渲染出口**：`useCanvasRenderer` 把 `SevenDimensionEngine.apply()` 的 `items` 画成光点（`drawCircle` + `adjustOpacity` 实现按值大小/按类别着色/按透明度）。布局用**确定性**模式（grid / around-same-center / center-outward-radial / left-to-right），刻意避开引擎默认的 `free-scatter`（`Math.random` 会导致渲染抖动与测试不稳）。
3. **NL 入口**：暴露 `parseNaturalLanguage` 输入框（"用光点表示每个专注会话。会话的专注时长决定光点的大小。所有光点围绕同一圆心排列。"），零配置生成可视化——这正是蓝图"数据视觉逻辑语言"的体验落点。
4. **宪法合规**：数据源仅本地 `storage`，零网络/外部调用；视图不引入任何 `fetch/http/cloud` 依赖。

#### IO 契约映射（storage 字段 → SevenDimensionDataItem）
| 主题 | 源类型 / 函数 | id | values（数值） | categories（类别） | timestamp（ms） |
|---|---|---|---|---|---|
| sessions | `FocusSession` / `getSessions()` | `s.id` | `elapsedMin`(elapsed/60000)、`plannedMin`、`focusRatio`(≤1) | `mode`、`status` | `startedAt`→ms（回退 `completedAt`） |
| notes | `Note` / `getNotes()`（过滤 `deletedAt`） | `n.id` | `tagCount`、`titleLen` | `priority`、`archived`(active/archived) | `createdAt`→ms |
| emotions | `EmotionRecord` / `getEmotions()` | `e.id` | `weight`(=1) | `type` | `createdAt`→ms |
| anchors | `Anchor` / `getAnchors()` | `a.id` | `driftCount` | `priority`、`done`(done/pending) | `targetDate`→ms（回退 `createdAt`） |

> 默认七维配置（`buildDefaultConfig(subject)`）按主题给出形状/大小字段/类别着色/确定性布局，使"零配置"即有合理视觉；NL 仅叠加覆盖用户显式描述的维度。

## ADR-M2：性能自适应引擎（核实接线，非从零构建）

### Status
**Done (verified 2026-08-16)** —— 核心模块 `modules/adaptive/`（device-tier + useAdaptiveQuality + barrel + 单测）**早已实现**；本轮回填了原本零消费的孤儿旋钮（`animationEnabled` / `effectScale`）并接入 `CanvasRoom.vue`，四道闸门验证（M2 相关文件全绿）。

### Context（误判更正）
> ⚠️ **M2 与 M1 是同一类误判**：原 ADR 据单一名词 grep 判定"无设备分级/质量自适应 → 从零构建"。实际引擎位于 `modules/adaptive/`：
- `device-tier.ts`：`classifyTier(input)` 纯函数（cores≥8:+2/≥4:+1 + mem≥8:+2/≥4:+1，软件渲染扣 2；≥4→high，≥2→mid，否则→low）+ `detectDeviceTier()` 浏览器探测（`hardwareConcurrency`/`deviceMemory`/WebGL `UNMASKED_RENDERER`，非浏览器安全降级 `mid`）。**零外联，符合宪法第1条本地私有**。
- `useAdaptiveQuality.ts`：`QualityProfile{tier,dprCap,particleScale,animationEnabled,effectScale}` + `PROFILES`(low/mid/high) + `useAdaptiveQuality()` 组合式（`detectedTier`/`override`/`effectiveTier`/`profile`/`setOverride`，覆盖经 KV `hf:adaptive-tier` 持久化）。
- `index.ts` barrel 统一导出。
- 测试：`__tests__/useAdaptiveQuality.test.ts`(4) + `__tests__/device-tier.test.ts`(7) 已覆盖。

**已接线消费者（本轮回查确认）**：
- `views/VisualizationStudio.vue`：`quality.profile.value.dprCap` 注入 Canvas 设备像素比上限。
- `modules/canvas/CanvasRoom.vue`：`quality.profile.value.particleScale` 缩放粒子密度（原有）。

**真实缺口（本轮回填）**：`QualityProfile` 含 4 个档位旋钮，但 `animationEnabled` 与 `effectScale` **计算出来却零视图消费**（孤儿）。其余重型视图（Astrolabe / StarMap3D 等 3D）亦未消费。

### Decision（已落地）
沿用 M1"孤儿→接线"范式，把两个孤儿旋钮接入最重的常驻画布 `CanvasRoom.vue` 的 `drawParticles`：
> 注：该门控最初由 commit `9b7e6fc` 提交，但本回合复核发现**当前工作树并未包含该改动**（与 HEAD 偏离，疑被后续编辑/重置抹除）。本回合重新应用该门控，使工作树恢复与 HEAD 一致，并重新跑四道闸门验证——本质是"恢复 + 验证"，非新写逻辑。
1. **`animationEnabled` 门控非必要动画**：`false`（low 档）时跳过粒子呼吸 `alpha` 振荡与连线辉光重绘——仅保留静态粒子点，低端设备省 CPU/GPU。
2. **`effectScale` 缩放连线辉光强度**：鼠标连线与粒子间连线的 `strokeStyle` 透明度整体乘以 `effectScale`（low=0.5 / mid=0.85 / high=1）。
3. **恒等保护**：high 档 `effectScale=1` 为恒等变换、`animationEnabled=true` 与既有行为逐字节一致；仅 mid/low 受影响，风险可控、不改动高端表现。
4. **Astrolabe / StarMap3D 等 3D 视图消费评估**：属更重的 WebGL/Three 渲染降级，超出"低风险接线"范围；**本回不强制接入**，留作独立 ADR（M2-ext），避免把未经验证的 3D 降级逻辑塞入已稳定的 3D 组件。

> 架构更正：原 ADR 拟新建 `utils/device-tier.ts` / `composables/useRenderQuality.ts` —— 实际 `modules/adaptive/` 已提供等价且更完整实现（含 KV 持久化覆盖），**直接复用，不另建平行文件**（避免 M1 式重复造轮子）。

## ADR-M3：家 3D 房间壳（一期 · Three.js WebGL，已落地）

### Status
**Done (verified 2026-08-16)** —— 一期 3D 壳已落地：`modules/home/useHomeRoomScene3D.ts`（Three.js WebGL，动态导入懒加载）+ `views/HomeSpace.vue` 接入 2D/3D 切换与拖拽环绕，四道闸门全绿。二期（星盘拖拽切场景）**deferred**。

### Context（误判更正）
> ⚠️ **M3 与 M1/M2 同属"差距误判"，但方向相反**：原 ADR 据"家为 2D 面板"判"缺失 / 从零构建（大）"。实际：
- `views/HomeSpace.vue` 已是**完整的 2D 房间场景切换器**：内置 `ROOM_COMPONENTS` 注册表（入口/衣帽间/厨房/餐厅/卧室/浴室/客厅/书房/庭院/阳台/储物/走廊共 12+ 房间组件），按 `currentSceneId` 经 `switchScene()` 切换渲染；含 `ROOM_SCENES` 标签页与走廊导航。**最重的"建房间 + 场景切换"骨架早已完成。**
- `components/home/*.vue`（LivingRoom/Bedroom/StudyRoom…）12+ 个房间组件均已实现并装配。
- **唯一的"3D"先例 `StarMap3D.vue` 是纯 CSS 3D**（`perspective`+`preserve-3d`+拖拽 `rotateX/Y`），**并非 Three.js**。原 ADR 称"仅 StarMap3D 有 3D"为真，但据此推"家需从零 3D"高估了工作量——家已有 2D 骨架，缺的只是 3D 表现层。
- ⚠️ **既有 3D 家视图（先前会话 `42cecd8` 已提交）**：`views/Home3DScene.vue` 是 **CSS 3D 等距**场景，独立路由 `/home-3d`（`router/index.ts:498` + `room-graph.ts` 节点 `home-3d`，branchFrom `home-space`），按 `HOME_ROOMS` 驱动 11 个房间瓦片、深链回 `/home-space?room=<id>`，自带 `Home3DScene.test.ts`(5)。本会话的 Three.js 壳是**另一个** 3D 入口（集成在 `HomeSpace` 主视图内的 2D/3D 切换），二者技术栈（CSS 3D vs WebGL）与入口（独立路由 vs 主视图切换）均不同，**曾并存**。→ **用户决策：退役 CSS `/home-3d`，保留 WebGL 主视图切换**（本回合已执行，见 Consequences）。

**技术选型（用户决策）**：经架构权衡（CSS 3D 零依赖·合宪 vs Three.js 真 WebGL·大包体违本地轻量），用户明确选择 **Three.js 真 WebGL 3D**。作为架构师已命名代价并落实两条风控：① **懒加载**——`three` 仅经动态 `import()` 在用户切到 3D 时进入运行时，2D 首屏零包体增量；② **不重写数据层**——12+ 房间组件与 `switchScene` 全复用，WebGL 只负责"3D 房间框 + 拖拽环绕相机"，2D 房间内容作为合成层叠在其上。

### Decision（已落地）
1. **3D 房间壳模块 `useHomeRoomScene3D.ts`**（动态导入，不进主包）：`createHomeRoomScene({ dprCap })` 返回 `{ mount, setRoom, rotateBy, dispose }`。内部用 `THREE.Scene`+`PerspectiveCamera`+`WebGLRenderer(alpha 透明底，合壳层约定)`，构建地面+三面粉墙的开放房间盒（`DoubleSide` 保证从内可见），材质 `MeshStandardMaterial` 取 `palette.base`、墙面 `emissive` 取 `glow`；灯光 `AmbientLight`+`PointLight` 均染房间光色。**按需渲染**：仅 mount/setRoom/rotateBy/resize 时 `renderer.render`，无空闲 rAF 循环（契合 M2 性能纪律）。
2. **颜色/灯光计算抽纯函数**（`hexToRgb`/`shade`/`derivePalette`）——由 `ROOM_SCENES[].atmosphereColor` 推导 `base/glow/glowEnd`，可在 jsdom（无 WebGL）下单测。
3. **接入 `HomeSpace.vue`**：`viewMode`('2d'|'3d') + `view-mode-toggle` 按钮；3D 态下 `await import('../modules/home/useHomeRoomScene3D')` 懒加载并 `mount(roomCanvas)`，把现有 2D `<component>` 包进 `.room-content--3d` 玻璃卡叠在 canvas 之上；指针拖拽（绑 room-viewport）调用 `rotateBy` 环绕相机；`watch(currentSceneId)` 在 3D 态同步 `setRoom({ glow })` 切换房间光色，不重建几何。`onUnmounted` 调 `dispose()` 释放 WebGL 上下文。
4. **M2 协同**：`dprCap` 由 `useAdaptiveQuality().profile.value.dprCap` 注入 `renderer.setPixelRatio`，低端设备自动降分辨率。

## ADR-M6：镜我独立路由（小，推荐首个落地）

### Status
**Done (verified 2026-08-16)** —— 路由 + 容器视图 + room-graph 节点 + 测试均已提交，四道闸门全绿（eslint 0 / madge 无环 / vue-tsc 0 / vitest 17 passed）。

### Context
`components/MirrorSelf.vue` 已实现（含 `:embedded` 模式、测试 `MirrorSelf.test.ts`），当前仅在 `AdvisorDock.vue` 内嵌使用。蓝图将其定位为"陈列而非叙事的年度对话面"，应是一个**可导航的房间**。

### 方案（实测落地）
- `router/index.ts` 已注册 `withRoomMeta({ path:'/mirror-self', name:'mirror-self', component:()=>import('../views/MirrorSelfView.vue'), meta:{title:'镜我'} })`（文件名实际为 `MirrorSelfView.vue`，非 ADR 原拟 `MirrorSelfRoom.vue`，功能等价）。
- 容器视图 `views/MirrorSelfView.vue`：渲染 `<MirrorSelf :embedded="true" />`，沿用项目 `useViewEntrance` 入场动效；房间根透明 + `min-height:100%` + 仅辉光（贴合壳层布局约定）；移动端收窄 padding。
- 导航入口：`engine/room-graph.ts` 已注册 `mirror-self` 节点（`group:'world'`, `branchFrom:'home-space'`, 邻接 `home-space/advisors/all-selves`），故星盘/房间地图/搜索/最近访问均可直达，**无需额外侧栏按钮**（与 `study`/`output`/`growth-garden` 等同机制）。
- **宪法合规（修正）**：镜我属个人「陈列而非叙事」面。`AdvisorDock` 内嵌 `MirrorSelf` **不受** `advisorEnabled` 门控（`enabled` 仅控 dock 在场态/问候，沉默默认=不出声而非隐藏镜面）。独立路由沿用同一语义 → **保持不门控**，是正确且一致的产品决策。ADR 原"受 advisorEnabled 门控"一句作废。

### Consequences
- 正面：最小改动兑现蓝图 M6，且为 M1 接线提供"容器视图"范式参考。
- 风险：低（单路由 + 单视图 + 现有组件；四道闸门可验证，madge 无环）。
