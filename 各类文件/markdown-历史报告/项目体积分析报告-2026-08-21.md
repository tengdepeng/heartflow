# Heartflow 项目体积分析报告

- 分析日期：2026-08-21
- 工作区：`E:\Heartflow\heartflow`
- 实测总体积：约 **8.5 GB**

## 一、体积构成明细

| 路径 | 体积 | 占比 | 性质 |
|---|---|---|---|
| `project/backend/src-tauri/target/debug` | 7.5 GB | ~88% | ❌ 废弃旧副本的 Rust 构建产物 |
| `project/src-tauri/target/debug` | 874 MB | ~10% | ⚠️ 真源 Rust debug 构建产物（可重建） |
| 顶层 `node_modules` | 89 MB | ~1% | ⚠️ 前端 npm 依赖（可重建） |
| `project/frontend/src` | 18 MB | <1% | ✅ 真实前端源码 |
| 两份 Rust `src` + 配置/文档/其他 | ~100 KB + 5 MB | <1% | ✅ 真实内容 |

**结论：约 99% 的空间是可重建的构建产物与依赖，真实源码仅约 20 MB（占比 ≈ 0.2%）。**

## 二、根因诊断

### 1. 存在两份 Tauri 后端树（核心症结）
- `project/src-tauri/` —— **真源**，活跃维护（最近修改 2026-08-18 ~ 08-20），其 `target/debug` 为 874 MB。
- `project/backend/src-tauri/` —— **废弃旧副本**，根目录停留在 2026-08-06 不再改动，整棵 7.5 GB 几乎全是它自己的 `target/debug`。与真源功能重复，是真正的"空间黑洞"。

### 2. 未清理的 Rust debug 构建产物
`target/debug` 含完整调试符号、未做优化，体积远大于 release。两份 debug target 合计约 8.37 GB。

### 3. 前端 npm 依赖
顶层 `node_modules` 89 MB，属标准依赖目录，可 `npm install` 重建。

### 4. 真实源码体量健康
`frontend/src` 18 MB + 两份 Rust 源码 ~100 KB，代码本身精简，无异常膨胀。

## 三、健康度评估

- 代码仓库本身**健康精简**，体积问题纯属"构建产物堆积"，非代码或架构缺陷。
- 这些产物**本不应入库**：应靠 `.gitignore` 屏蔽 `target/`、`node_modules/` 等。当前仓库未初始化顶层 `.git`（顶层无 `.git` 目录），版本控制状态需另行确认。

## 四、可释放空间与清理建议

| 动作 | 释放空间 | 风险 | 可逆性 |
|---|---|---|---|
| 删除 `project/backend`（废弃副本） | ~7.5 GB | 中（须先确认确为废弃） | 低（纯构建产物，真源在 `project/src-tauri`） |
| `cargo clean`（真源 target） | ~874 MB | 低 | 完全可逆（`tauri:dev` 自动重建） |
| 清理 `node_modules` 后 `npm install` | ~89 MB | 低 | 完全可逆 |

**推荐的 `.gitignore` 兜底规则**（若启用 git）：
```
target/
node_modules/
dist/
**/*.rs.bk
```

## 五、风险提示

- `project/backend` 删除为破坏性操作，**删除前须二次确认其确为废弃旧副本**（已掌握证据：根目录停留在 8/06、真源在 `project/src-tauri`、历史记忆亦记录 backend 为旧概念）。本次仅出报告，未执行任何删除。
- `cargo clean` / 删 `node_modules` 均为可重建操作，开发时 `tauri:dev` 与 `npm install` 会自动恢复，无数据丢失风险。

## 六、结论

"整个项目大"并非代码膨胀，而是**重复的废弃后端树 + 未清理的 Rust debug 构建产物**所致。清理后可释放约 8.3 GB（占总量 ~98%），且全部为可重建产物，不影响源码与开发流程。
