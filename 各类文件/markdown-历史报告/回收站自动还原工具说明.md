# 回收站自动还原工具 recycle_restore.py

> 应对本环境 `safe-delete` 护栏批量误删的防护/自动恢复代码。
> 路径：`E:/Heartflow/.workbuddy/skills/heartflow-safe-delete/recycle_restore.py`

## 一、背景与问题根因

本环境（Windows + Git Bash）叠加 `safe-delete` 护栏：落盘删除（`rm` / `git rm` 的磁盘环节）会被拦截并送入回收站。其"批量保护"存在误判 bug——

**`git rm <单文件>` 会把被删文件所在的整个目录一并扫入回收站。**

实测事故（2026-08-11）：`git rm src/components/NoteSticky.vue`（删 1 个孤儿组件）触发护栏，将整个 `src/components`（含 `__tests__`/`data-sovereignty`/`knowledge`/`home`）共 **86 个跟踪文件** 一次性送入回收站，全量测试从 304 全绿骤降为 294 失败。

**根因级防护**：删跟踪文件改用 `git rm --cached <path>`——它**只改 git 索引、完全不触碰磁盘**，因此护栏（拦截的是落盘删除）永远不触发。文件仍在磁盘（变未跟踪），删除意图已记入索引，提交即生效。

## 二、工具功能

封装 `$I` 文件解析（version2：size@8 / time@16 / path@28，UTF-16LE）+ 回收站 `$R` 原路还原，三个子命令：

| 命令 | 作用 |
|------|------|
| `check-git` | 扫描 git 工作树中"被跟踪但磁盘缺失"的文件（事故早期预警） |
| `scan` | 列出回收站中匹配路径的已删条目（原始路径、删除时间、$R 是否还在） |
| `restore` | 把匹配条目原路还原回磁盘；默认 `--dry-run` 预览，已存在目标跳过，仅 `--force` 覆盖 |

通用参数：`--match`（路径子串，不区分大小写、自动归一化 `\`/`/`）、`--drive`（默认 E）、`--dry-run`、`--force`。

## 三、用法（用托管 Python）

```bash
PY="C:/Users/tengxiaosu/.workbuddy/binaries/python/versions/3.13.12/python.exe"

# 事故预警：哪些跟踪文件在磁盘上不见了？
"$PY" recycle_restore.py check-git --root E:/Heartflow

# 定位：回收站里某路径下有哪些已删条目？
"$PY" recycle_restore.py scan --match "heartflow/project/frontend/src/components" --drive E

# 预览还原计划（不写盘）
"$PY" recycle_restore.py restore --match "heartflow/project/frontend/src/components" --drive E --dry-run

# 真正还原（还原后务必跑四道闸门）
"$PY" recycle_restore.py restore --match "heartflow/project/frontend/src/components" --drive E --force
```

## 四、实测验证（2026-08-11）

- `check-git`：正确列出 5 个有意删除项（benchmark/docs），无误报。
- `scan --match ".../src/components"`：精确找到事故当天（12:00:37–38）**57 个组件条目**，$R 数据文件仍在回收站，可原路还原。
- `restore --dry-run`：正确显示"目标已存在 → 跳过"（组件已于上一轮还原），证明还原计划与跳过逻辑正确；写盘分支使用标准库 `shutil.copy2` / `copytree`。

## 五、恢复标准流程（期望正常状态）

1. `check-git` 发现大范围缺失 → 先不要 `git commit` 或再跑落盘命令。
2. `scan` 定位回收站条目，`restore --dry-run` 预览。
3. `restore --force` 还原（仅复制回收站内容回原路径，不清空回收站）。
4. 补齐回收站缺漏项：`git restore --worktree -- <目录>`（从索引）或 `git checkout HEAD -- <文件>`（从最近提交，丢失未提交改动）。
5. 重放自己的未提交编辑（用会话 Edit 前后文）。
6. 跑四道闸门确认：`vue-tsc` / `vitest` / `eslint --quiet` / `madge` 全绿 = 恢复正常。
