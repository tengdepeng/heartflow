## 一、载体生命周期闭环：原报告判断需勘误

原报告"技术债/缺口"中"载体生命周期演化无运行闭环（`LIFECYCLE_STAGES` 仅 `CanvasCarrier.vue` 读取显示）"**对念珠载体（JadeBeadCarrier）不成立**：

- `modules/carrier/index.ts` 的 `autoLifecycleCheck()` 在**每次拨珠**时真实推进 `newborn→growing→mature→aging`；
- `retireCarrier` 自动生成遗志、`inheritCarrier` 做传承（珠数精华转移 + 遗志继承）。
- 即念珠载体闭环**已完整实现且接线**，原结论为过时判断。

**真实缺口在幕僚载体（AdvisorCarrier，蓝图第四部分载体编辑器）**：

- 数据模型与按生命阶段形态覆盖（`carrier.stages: Partial<Record<AdvisorCarrierStage, AdvisorCarrier>>`）齐全，`carrierResolveStage` 能解析**指定阶段**的形态；
- 但**没有任何运行时依据 tenure / 亲密度 / 退休推导幕僚"当前"生命阶段**——`stage` 参数长期由调用方手动传入，从不被自动推进。蓝图16:585 要求的"诞生→成长→成熟→衰老→传承"在幕僚载体上缺乏运行推导。

## 二、已实施修复（选项4：幕僚载体生命周期演化闭环）

- `types/advisor.ts` 新增 `advisorCarrierStageOf(profile)`：纯函数，按 `createdAt`(tenure) / `affinity` / `retired` 推导当前阶段
  （`birth <30d` → `growth <180d` → `mature <365d`；`≥365d` 时亲密度≥40 仍 `mature`，否则 `aging`；`retired` → `legacy`）。不落盘，渲染时按需解析。
- `AdvisorDock.vue`、`AdvisorHub.vue` 渲染时按推导阶段解析载体形态，闭环闭合——用户在载体编辑器为每个生命阶段设置的形态，会随幕僚年龄/亲密度自动呈现。
- 单测补充于 `modules/advisor/__tests__/carrier-io.test.ts`（birth/growth/mature/aging/legacy 推导覆盖）。
- 顺带修复 `views/__tests__/AdvisorHub.test.ts` 既有缺陷：`vi.mock('../../types')` 仅 stub `AFFINITY_TIERS`，导致 `CARRIER_STAGE_ORDER` / `carrierGlyph` / `carrierIsImage` / `advisorCarrierStageOf` 等导出为 `undefined`、子组件 `AdvisorCarrierEditor` setup 崩溃。改为 `importOriginal` 保留真实导出、仅覆盖 `AFFINITY_TIERS`。
