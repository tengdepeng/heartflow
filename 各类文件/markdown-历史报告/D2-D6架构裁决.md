## ADR-D6：P2P 同步引擎默认关闭 —— 合规，闭环

### Status
**Closed / 无需改动**（实测符合宪法第 1 条「本地私有」与「所有通道默认关闭」）

### Context
差距清单 D6 标注：需确认 `modules/sync`（P2P 增量同步引擎）是否默认关闭、有无隐藏自动同步。宪法第 1 条要求数据不出设备、所有通道默认关闭。

### Decision / 核查结论
逐项核验 `project/frontend/src/modules/sync/`（`index.ts` + `types.ts`）+ 全 `src` 自动调度扫描：

| 核查点 | 实测结果 | 结论 |
|---|---|---|
| `DEFAULT_SYNC_CONFIG.autoSyncInterval` | `0`（"0 表示不自动同步"） | ✅ 无自动同步定时器 |
| 同步目标 `targets` 默认值 | `[]`（空数组） | ✅ 无目标则 `sync()` 直接返回错误，无法运行 |
| `sync()` 触发方式 | 仅显式调用（`useSync().sync(targetId,...)`） | ✅ 无启动期/后台自启 |
| 全 `src` 自动调度扫描（`setInterval`/`setTimeout`/`useSync(`/`.sync(`） | 命中均在 `automation.ts`（用户自动化引擎）、`AdvisorDock`、`stores/timer`（专注计时）等**无关模块**；sync 模块内零自动触发 | ✅ 无隐藏同步 |
| 传输方式 | `downloadSyncData()`（导出 JSON 文件）、`importSyncFile()`（从文件导入）、`createSnapshot()/restoreSnapshot()`（本地快照） | ✅ 纯 P2P / 文件 / 本地，不触任何服务器 |
| 外部网络依赖 | sync 模块零 `fetch/axios/http/reqwest` 调用 | ✅ 符合第 1 条本地私有 |

### Consequences
- 正面：默认态"绝对安静 + 本地私有"在同步子系统上成立，D6 从"待核实"转为已闭环。
- 注意（非阻塞）：Rust 后端 `project/backend/src-tauri/Cargo.toml` 含 `reqwest`（HTTP 客户端）。它不在 sync 模块内，仅可能服务于可选外部 AI 引擎（设备直连、Key 仅本地）。sync 本身不经过它，不影响 D6 结论；如需更严格，可单列一条核查「AI 引擎是否设备直连」。

## ADR-D2：双份 Tauri 配置 —— 主从已定，路径 bug 已修，orphan 待清

### Status
**Partially Resolved** —— 主从确立 + 生产构建路径 bug 已修；旧树删除待用户确认。

### Context
`heartflow/` 下存在两份 `tauri.conf.json`：
- `heartflow/src-tauri/tauri.conf.json`
- `heartflow/project/backend/src-tauri/tauri.conf.json`

需确认构建实际引用哪一个，并消除配置漂移。

### 证据链（主从判定）
1. **构建脚本指向**：`project/frontend/package.json` → `"tauri:dev": "tauri dev --project-dir ../backend"`。显式把 Tauri 工程目录钉在 `project/backend`，即 `project/backend/src-tauri` 为**唯一真源**。
2. **构建日志佐证**：`tauri-dev-run*.log` / `project/frontend/tauri_dev_test.log` 均显示 `Watching .../project/backend/src-tauri`、`Compiling heartflow v0.1.0 (.../project/backend/src-tauri)`。
3. **迁移文档佐证**：`doc/Blueprint-Mapping.md:150-153` 明确记录了本次迁移（`tauri:dev` 改 `--project-dir ../backend`、`frontendDist` 改为 `../frontend/dist`、`.gitignore` 新增 `project/backend/src-tauri/target/`）。
4. **依赖演进佐证**：canonical `Cargo.toml` 已演进（含 `rusqlite` 本地库 / `reqwest` / `tauri-plugin-fs` / `-autostart` / `-global-shortcut` / `-notification`）；orphan `heartflow/src-tauri/Cargo.toml` 仅有 `tauri` + `tauri-plugin-opener`，明显为**重构前旧树**。

### 已落地修复（canonical 配置路径 bug）
`project/backend/src-tauri/tauri.conf.json` 的 `frontendDist` 由 `"../frontend/dist"` 改为 `"../../frontend/dist"`。
- **原因**：Tauri v2 的 `frontendDist` 相对 `tauri.conf.json` 所在目录解析。`project/backend/src-tauri` + `../frontend/dist` → `project/backend/frontend/dist`（**不存在**）；正确值 `../../frontend/dist` → `project/frontend/dist`（**真实前端产物**）。
- **影响**：仅 `tauri build` 生产构建（dev 走 `devUrl: http://localhost:1001`，不受影响）。两份既往修复文档（overview-white-screen-fix.md:35、overview-functional-audit-2026-08-09.md:49）均独立指出同一 bug 与同一修复值，本次落地对齐。
- **风险**：极低、单行、可逆。

### 待决：删除 orphan 旧树 `heartflow/src-tauri/`
- **判定**：该目录为重构前遗留，构建与文档均已不引用（除 `doc/Blueprint-Mapping.md` 的树状图示意与若干分析报告的历史提及）。继续保留会造成"双配置漂移"误导。
- **推荐动作**（git 可逆，仅移除受跟踪源文件；`target/` 为 gitignore 构建缓存，不纳入）：
  ```bash
  # 在 E:\Heartflow 根（git 根 = E:\Heartflow）执行
  git rm -r --cached heartflow/src-tauri   # 解除跟踪（保留磁盘）
  # 确认无误后再物理删除磁盘源文件；target/ 构建产物可随时手动清理
  ```
  > ⚠️ 注意：`heartflow/src-tauri/target/debug/.cargo-build-lock` 历史上属另一用户 `雨佳\CodexSandboxUsers`，普通账号可能无权删除该锁文件；建议优先用 `git rm --cached` 解除跟踪，磁盘旧树待有权限时清理，避免删除命令因权限失败而中断。
- **需用户确认**：删除结构性目录属不可逆动作（尽管 git 可恢复），且存在上述权限坑，故**暂停执行**，待用户明确授权后再跑上述命令。

### Consequences
- 修复路径 bug 后：生产 `tauri build` 不再因 `frontendDist` 解析失败而白屏/失败。
- 删除 orphan 后：彻底消除双配置漂移，新接手者可一眼定位唯一真源 `project/backend/src-tauri`。
