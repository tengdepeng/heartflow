# ADR-014：后端 `src-tauri` 宪法合规审计

- **状态**：已审计 · 部分修复已落地（`0ae0fa4` 之后）
- **日期**：2026-08-17
- **作者**：SoftwareArchitect（心流工坊合规车道）
- **关联**：比对报告《蓝图文件vs代码比对报告-2026-08-17.md》（前端 `src` 已全覆盖）；前序 ADR-013（第4条对称增强，提交 `0ae0fa4`）

---

## 1. Context（背景与动机）

前序比对报告与合规车道已对**前端 `src`** 做全覆盖：宪法引擎的第1条网络扫描（`fetch/axios/http/cloud/remote/websocket/Notification` 零命中即满足本地私有）、第2条覆盖层、第4/5/8条运行时检测均闭环。

但宪法合规存在**审计盲区**：应用真正的「数据离开本设备」出口在 **Rust 后端 `src-tauri`**——前端 AI 调用经 Tauri 命令（`cmd_ai_*`）委托后端 `reqwest` 发往外部模型 API。前端扫描只对 `src` 生效，对后端委托路径是**假阴性**。本次审计补齐后端，给出事实基线与差距清单。

后端代码规模：`src/` 下 6 个文件（`lib.rs` / `main.rs` / `ai_agent.rs` / `storage.rs` / `sqlite.rs` / `touchpoints.rs`）+ `Cargo.toml` + `tauri.conf.json` + `capabilities/`。

---

## 2. 事实基线（逐文件核查）

| 文件 | 职责 | 网络/外部依赖 | 宪法相关结论 |
|---|---|---|---|
| `storage.rs` | 本地 JSON 存储（`app_data_dir/heartflow/storage.json`） | 无 | ✅ 纯本地 |
| `sqlite.rs` | 本地 bundled SQLite（`heartflow.db`，WAL） | 无（`cmd_sqlite_execute` 为**泛型 SQL 透传**，属本地攻击面而非网络） | ✅ 纯本地；⚠️ 见 §5 |
| `touchpoints.rs` | 自启/全局快捷键/覆盖层窗口/系统状态 | 无（`cmd_get_system_state` 仅读自身窗口标题，注释明示「严格本地、不跨进程窥探第三方」） | ✅ 隐私合规 |
| `ai_agent.rs` | **AI 代理**：`reqwest::blocking::Client` 调用户可配置 `model_url` | **⚠️ 唯一真实网络出口** | 见 §3.1 |
| `lib.rs` / `Cargo.toml` | 插件注册与依赖 | `reqwest` / `tauri-plugin-notification`(已移除) / `shell` / `opener` / `fs` | 见 §3.2 / §3.3 |
| `tauri.conf.json` | 打包/窗口/安全 | `devUrl: localhost:1001`、`csp: null`、`--remote-debugging-port=9222` | 见 §5 |
| `capabilities/*.json` | Tauri 权限能力 | 已移除 `notification:*`（见 §3.2） | — |

**唯一程序化数据出口 = `ai_agent.rs::AiAgent::call_api`**（`reqwest` POST 到 `config.model_url`，默认 OpenAI 云端）。其余均为本地文件/SQLite 或用户本地 OS 能力（自启、快捷键、覆盖窗口）。

## 3. 逐条核查结论

### 3.1 第1条 · 本地私有（内核级·不可关闭）

**现状**：
- 存储层（JSON + SQLite）全本地 ✅。
- AI 出口**用户可配置**（`model_url`），且前端已内置 `local` 类型（Ollama `http://localhost:11434`）——即**本地优先是支持项**，符合第2条超级自定义。
- 前端 `engine/data-outflow.ts` 已实现「守护室·数据流出日志」：每次外部 AI 调用记录 `{时间, 渠道, 净化后端点, 摘要}`，**仅记端点不记载荷**（符合蓝图模块六「完整数据流出的日志」）。
- **但存在三处缺口**：
  1. **宪法网络扫描对后端是假阴性**：前端扫描器只看 `src`，看不到 `cmd_ai_*` 委托的 `reqwest` 出口，导致「第1条零网络请求」判定失真。
  2. **默认云端优先**：`AiAgentConfig::default().model_url` 原硬编码 `https://api.openai.com/v1/chat/completions`；前端 `DEFAULT_OPENAI_PROVIDER.baseUrl` 同为云端。开箱即暗示云端优先，与「默认私有」姿态相悖。
  3. **无 fail-closed 同意闸**：外部（非 localhost）调用前有日志但**无拦截/无显式同意**；`complianceOverride` 体系未覆盖后端出口。

**已落地修复（本 ADR）**：
- ✅ `ai_agent.rs` 默认 `model_url` 置空 → 开箱即 `configured=false`、零外部调用（`call_api` 在空 URL 时直接报错返回），实现 fail-closed 默认私有。

**建议（未实现，留待后续轨道）**：
- 在宪法引擎第1条扫描中**显式声明**后端 AI 出口为「用户显式配置、本地优先可选、且每次流出已记入数据流出日志」的已认知例外，消除假阴性。
- 为外部（非 localhost）AI 端点增加**显式同意闸 + `complianceOverride.allowExternalAI`（默认 false）**，与前端 `isOsNotificationBlocked` 同口径 fail-closed。
- 将前端 `DEFAULT_OPENAI_PROVIDER` 默认从云端改为需要用户主动选择（或默认 `local` 模板）。

### 3.2 第5条 · 无推送（fail-closed 默认阻断）

**现状**：
- 前端 OS 通知走 Web `Notification` API，且被 `isOsNotificationBlocked()`（读 `complianceOverride.notificationBlocked`，默认 `true`=阻断）闸控 → 前端侧 fail-closed ✅。
- 后端 `tauri_plugin_notification` 插件虽注册且 `capabilities/default.json` 授予 `notification:*`，但**前端通知路径从未调用该 Tauri 插件**（无任何 `@tauri-apps/plugin-notification` 引用）。即授予了一项**未使用、且绕过前端 fail-closed 闸的潜伏推送能力**——违反最小权限。

**已落地修复（本 ADR）**：
- ✅ 移除 `tauri_plugin_notification`：删 `Cargo.toml` 依赖、`lib.rs` 注册、`capabilities/default.json` 三条 `notification:*` 权限。`gen/schemas` 已被 gitignore，将由下次 `tauri build` 自动重生（不含 notification）。

### 3.3 第2条 · 超级自定义（用户覆盖层）

**现状**：
- AI 端点完全用户可配置（URL/Key/模型/温度/Token），支持本地模型 → 符合「形象/性格/行为边界/主动程度由用户定义」精神 ✅。
- **缺口**：前端 `complianceOverride` 覆盖层（7+1 字段）是**前端单端概念**，后端对用户的合规选择**无感知**。后端原生行为（AI 出口、自启、快捷键）不受覆盖层约束。属架构一致性待补项。

**建议**：通过 Tauri 命令把相关 `complianceOverride` 键下发后端（如 `allowExternalAI` 闸 AI 出口），使前后端配置同轴。

## 4. Decisions（本次已决）

| # | 决策 | 取舍 / 代价 |
|---|---|---|
| D1 | 后端 AI 默认 `model_url` 置空（fail-closed 默认私有） | 代价：新用户未配置时 `cmd_ai_*` 返回「未配置模型 URL」而非静默云端默认；这正是期望的私有默认姿态。 |
| D2 | 移除未使用的 `tauri_plugin_notification`（插件+能力+依赖） | 代价：若未来要用 Tauri 原生通知需重新接入并接 `isOsNotificationBlocked` 闸；当前前端走 Web Notification 不受影响。收益：消除潜伏未闸推送能力，最小权限。 |

两项均已改 `src-tauri` 源文件，`cargo check` 验证中（见 §6）。

---

## 5. Observations（安全加固项，非宪法硬违约，建议跟进）

1. **CSP 关闭**：`tauri.conf.json → app.security.csp: null`。本地 Tauri 应用若加载任何远端内容或存在 XSS，关闭 CSP 会放大风险。建议设最小 CSP（如 `default-src 'self'` + 必要 `connect-src` 白名单）。
2. **远程调试端口**：`additionalBrowserArgs: --remote-debugging-port=9222`。开发便利，但须确保**生产构建剥离**（否则本地暴露调试接口）。
3. **`shell:allow-open` 未收窄**：允许打开任意 URL/文件。建议按 Scheme/Path 收窄，避免成为弱 egress 向量。
4. **泛型 SQL 透传**：`cmd_sqlite_execute` / `cmd_sqlite_query` 把任意 SQL 暴露给前端。属本地攻击面（不触网），但建议以白名单/参数化查询收窄，避免前端逻辑错误破坏库完整性。

## 7. Consequences（后续影响）

- **更容易**：后端出口姿态与第1条「默认私有」对齐；消除一项潜伏未闸能力；宪法审计盲区收窄（仅剩「扫描器前端单端」需声明例外）。
- **更难 / 待办**：前端 `DEFAULT_OPENAI_PROVIDER` 默认与后端默认目前不一致（前端仍云端默认）；需后续轨道统一为本地优先/显式选择，并补「外部 AI 同意闸」。
- **一致性**：前端 `complianceOverride` 与后端行为同轴化（D2 起步，D3 待做）。

## 8. 落地跟踪（2026-08-17 深夜补充）

§7「更难 / 待办」中「前端仍云端默认」一项**已落地**：

1. **前端 AI 默认真正本地优先 / fail-closed（对应 #340）**：
   - 根因：`engine/storage/core.ts` 的 `DEFAULT_CONFIG.ai.providers.default.baseUrl` 仍是云端 `'https://api.openai.com/v1'`，这才是运行时权威默认（`getAIEngineConfig()` 走 core.ts 种子；`types.ts` 的 `DEFAULT_OPENAI_PROVIDER` 虽已置空，但仅当 `appConfig.ai` 为假时兜底，实际永不触发）。属半完成迁移漏网。
   - 改动：core.ts 默认 `baseUrl` 改为 `''`（注释对齐第1条·本地私有·fail-closed）；修复陈旧测试 `engine/ai/__tests__/types.test.ts:25`（原断言云端 URL，与已置空源码矛盾），并新增「默认不预设云端地址（fail-closed）」专测。
2. **第1条扫描显式声明后端 AI 出口为已知例外（对应 #341）**：
   - 前端扫描器 `engine/__tests__/constitution-compliance.test.ts` 的 SANCTIONED_NETWORK_FILES 注释扩展：明确 `provider.ts` fetch 受用户 baseUrl 门控、`tauri-provider.ts` 经 Tauri Bridge 委托 Rust `cmd_ai_*`→reqwest（后端默认空 model_url fail-closed），该后端出口为前端单端扫描的【已知例外】，由后端宪法审计独立保证。
   - 后端 `src-tauri/src/ai_agent.rs` 新增 `#[cfg(test)]` 单测 `default_ai_config_is_fail_closed` + `call_api_refuses_empty_config`，从源码锁死后端 AI 出口 fail-closed 默认。

**验证**：前端 targeted vitest（types.test 8 + constitution-compliance 24 = 32 全绿）；eslint 三文件 0 错；storage+ai 全量 362 全绿；`cargo test --lib ai_agent` 2 新测全绿（后端整库编译通过）。

**落地下落（2026-08-18 收尾 · 本轨道）**：原「仍待办」三项均已提交闭环：
- ① 外部 AI 端点显式同意闸：`363ee00`（前端 `engine/ai/external-gate.ts`，默认关闭、拦截即弹窗告知）。
- ② 前后端 `complianceOverride` 同轴（后端 AI 出口同意闸）：`23527c7`（`ai_agent.rs` 增 `allow_external_ai` + `tauri-provider.ts` 注入 consent）。
- ③ §5 安全加固：`dbea0c3`（剥离 `--remote-debugging-port=9222`；`plugins.shell.open` 正则收窄到 `https://heartflow\.app`；`external-gate` 拦截即弹窗）。CSP 经用户决策保留 `null`——采用「同意闸 + 调用时弹窗告知」而非静态硬编码拦截，以免阻断已同意的远程 AI。
- ④ 泛型 SQL 透传收窄（本轨道收尾）：`sqlite.rs` 对 `cmd_sqlite_query` 限为只读 SELECT/WITH、对 `cmd_sqlite_execute` 限为 INSERT/UPDATE/DELETE/事务控制并强制 DELETE/UPDATE 带 WHERE，拒绝 DDL/元命令。两泛型命令无前端调用点（KV/backup 走固定 SQL），纯本地面，为零成本防御。

**并行会话已落地的其余 A/B/C 类（非本轨道，仅记以消除文档过时）**：A2.3 批3（`8cece88` 接线 emotion:visualization + relation:auto-analyze）、B1 本地快照文件回路（`978223c`）、B1.4 局域网快照服务（`e45e6ea` 后端 + `10399f2` 前端适配器）、B2 锁屏模式（`1e84c74`）、C1 轻量近义层（`10399f2`）、C2 运行时文案中性检测（`94b92cf`）。
