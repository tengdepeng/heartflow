## 三、核心缺口与修复

### 缺口 1：`NoteLayer` 从未挂载（最大缺口）
`NoteLayer` 含编辑器、笔记板、新建入口，但 `App.vue` 从未引用它；且它 `inject('noteBoardVisible')` 也从未被 `provide`。结果：画布便签"看得见、能拖"，却**无法编辑、无法新建、无法打开笔记板**。

**修复**：`App.vue` 中 `import NoteLayer` 并在根挂载 `<NoteLayer />`，同时 `provide('noteBoardVisible', ref(false))`。

### 缺口 2：跨组件状态不同步（隐形 bug）
`CanvasNotes` / `NoteLayer` / `NoteBoard` 此前各自调用 `useNote()`，**每次调用新建独立响应式状态**（非单例）。后果：在画布新建的便签，其数据只在 CanvasNotes 的实例里，编辑器（NoteLayer 实例）保存时按 id 找不到该便签 → **保存静默失效**。

**修复**：三处统一改用 `getNoteStore()` 模块级单例（与项目"模块级单例 composable"约定一致）。新增 `note-singleton.test.ts` 固化此不变量。

### 缺口 3：浮动便签双渲染
`NoteLayer` 自带 `sticky-notes-layer`（用 `NoteSticky` 以视口 % 渲染），与画布内 `CanvasNotes` 会以**两份重叠便签**重复显示。

**修复**：移除 `NoteLayer` 的 `sticky-notes-layer` 与 `NoteSticky` 引用，画布浮动便签**只由 `CanvasNotes` 渲染**（画布相对坐标 + ambient 处理更贴合"画布便签"语义）。`NoteSticky.vue` 现为孤儿组件（保留，待后续清理）。

### 缺口 4：画布"直接新建"无实现
`CanvasNotes` 空状态提示"右键画布添加"，但无任何创建交互。

**修复**：在 `CanvasNotes` 加常驻「＋ 便签」按钮（右上角，pointer-events 安全，不阻挡画布结晶交互），点击即在画布新建便签并 `emit('edit')` → `CanvasRoom` 派发 `hf:note-edit` → `NoteLayer` 打开编辑器。

## 五、功能闭环（现在可用）

- **显示 / 拖拽 / 钉住 / 最小化 / 关闭**（画布内 `CanvasNotes`，本地坐标，ambient 降级）。
- **编辑**：点击便签或「＋ 便签」→ 打开 Markdown 编辑器（标题/标签/正文/预览/双向链接，Ctrl+S 保存）。
- **笔记板**：右下角 FAB 打开，支持搜索、按更新/创建/标题排序、新建、贴为便签/收入面板、删除。
- **持久化**：全部经 `engine/storage` KV 本地存储，符合"本地私有"宪法条款。

## 七、安全护栏提示（复用修正）

本环境 `safe-delete` 护栏现已**同时拦截** `node fs.rmSync`（vite emptyDir）与 **Git Bash `rm`**（与早前"bash rm 不在其列"的笔记不符）。`vite build` 清空旧 `dist/`（>50 文件）会被拦为 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`，**与代码无关**。`dist/` 为纯构建产物（git 未跟踪）。验证打包可改用全新 `--outDir`（如 `node_modules/.hf-dist-verify`）绕开护栏，无需删除旧 dist。
