## 二、版本完整性判定（核心问题）

> **问题：融合版蓝图是不是所有蓝图的最新融合版？**

### 2.1 结论
**不是单一文件意义上的"最新完整融合版"。** 准确表述：

- `融合版蓝图15` 是**字面意义的融合蓝图**（把 13+14+ 合并成一份施工级文档），但它**止于 2026-07-24**。
- `蓝图17`（2026-08-11）**更新**，且**显式以蓝图15 为底本**，定位为"APK 融合补充版"——它**不是独立重写的融合版**，而是叠加在 15 之上的**增补层**：
  - 增量 A：把 130 款竞品 APK 的可比功能融合进 30 个房间（含"拒绝清单"：云端/广告/推送/排行等）。
  - 增量 B：**宪法分级落地**——第 1–2 条标【强制·内核级·不可关闭】，第 3–52 条统一降为【可选·可关闭】。
  - 蓝图17 自述："**完整逐字段规格仍以蓝图15 为准**"。

### 2.2 判定矩阵
| 维度 | 融合版15 | 蓝图17 | 最新完整蓝图 = ? |
|---|---|---|---|
| 施工级规格（数据模型/接口/性能） | ✅ 权威 | ➖ 引用 15 | **15** |
| 宪法分级（1-2 强制 / 3-52 可关） | 隐含（"内核级/弹性"） | ✅ 显式表格 | **17**（更明确） |
| 竞品 APK 功能融合映射 | ➖ 无 | ✅ 第五部分映射总表 | **17** |
| 模块/房间清单（30+2 基础设施） | ✅ 全 | ✅ 沿用 15 | **15=17** |
| 落地路线图（P0–P2 × 五阶段） | ✅ 第十三部分 | ✅ 沿用并细化下一步 | **15+17** |

### 2.3 发现的 Gap（版本管理层面）
- **G-V1（中）**：当前**不存在单一文档同时包含 蓝图15 全量规格 + 蓝图17 增补**。开发者需同时打开两份文件，易遗漏 17 的宪法分级/拒绝清单。
- **G-V2（低）**：缺少"版本谱系 README"——根目录散落 蓝图13/14+/15/17 四份 + 废弃 10 份，无索引说明谁为准、谁已废弃。
- 谱系图：
```
蓝图13 ─┐
        ├─► 融合版蓝图15 (Jul24, 全量施工规格) ──► 蓝图17 (Aug11, APK融合+宪法分级叠加)
```

## 五、技术约束解析

### 5.1 硬约束（不可关闭）
- **第 1 条 · 本地私有**：数据永在本地，不上传/不云端/不经服务器；云端备份仅用户主动触发且自加密；官方不提供云端存储。**离线可用是硬约束**（字体走本地/系统回退，禁外部 CDN 强依赖）。
- **第 2 条 · 超级自定义**：交互→视觉→房间结构→宪法本身（前两条除外）均可改；交互引擎原子化，可存"交互风格包"分享。

### 5.2 弹性宪法（第 3–52 条，可选·可关闭）
每条标注"影响房间 / 默认建议"。典型：心流第一、数据驱动探索、主动式探索、无脸人陪伴、静默留白、安全与永续、沉默的默认(52) 等。

### 5.3 价值观红线（功能边界，弹性但明确）
**禁止**：推送轰炸、广告、诱导打卡、制造焦虑、排行榜、社交压力、积分、连续签到、"你已落后 XX%"。所有外部驱动类设计在守护室被挡下。

### 5.4 架构约束
- 共鸣协议层**只定规则接口**（交互/业务/AI/知识接引/数据引渡/自动化/线程/扩展），不绑定实现。
- 七层 + 贯穿层，插件生态沙箱与权限透明。
- 性能自适应（蓝图17 第三部分第一层点名"性能自适应"）属真实待建能力（见差距清单 M2）。

### 5.5 设计系统硬约束（DESIGN.md，生效级）
- 唯一品牌色 = 暖琥珀 `--accent`；青/蓝/紫仅语义点缀，**禁 AI-slop（青紫渐变/霓虹/高饱和平涂）**。
- **禁硬编码 HEX**（除非一次性装饰）；颜色走 CSS 变量。
- 壳层 z 栈：`.app-base-bg` z-index **必须 0（不可 -1）**；房间根背景 **必须 transparent**（仅 `::before/::after` 辉光）。
- 唯一滚动容器 `.main-content`；视图根 `min-height:100%`，**禁 `height:100vh`**。
- 浮层 `position:fixed` 避让 220px 侧栏（移动端避让 48/56px）。
- 字体走系统/本地回退，离线可用。

## 六、依赖关系解析

### 6.1 跨房间基础设施依赖（自底向上）
- **模块〇 数据可视化自定义体系** → 所有房间可视化（雷达图/三环/进度环/克制范式）的底座。
- **模块十四·五 应用空间自定义体系** → 动律之间(二十)/自律工坊(十六)/应用感知的数据源（仅脱敏元数据，本地）。
- **主题引擎 `stores/style.ts`** → 全局 CSS 变量 + `body` 背景；单房间覆盖经 `useRoomStyle.ts`。

### 6.2 引擎层依赖
- 共鸣协议层定义接口 → 可插拔引擎层（交互/AI/呈现）实现 → 插件化调度层注册 → 功能插件生态层消费。
- AI 引擎：默认 `enabled=false`，支持本地 Ollama；云端端点需用户自配（非默认外联）。

### 6.3 幕僚系统跨切面依赖
- `useAdvisor()`(真实层) → `AdvisorHub.vue`(幕僚阁) + `AdvisorDock.vue`(Home 陪伴面) + `MirrorSelf`(镜我) + 载体编辑器。
- 载体系统 `AdvisorCarrier` / `carrier-io`（本地导入降采样 + `.carrier` 本地分享，`assertShareLocalOnly('local')` 兜底）。

### 6.4 首屏锚定依赖（星图 → 房间）
星图首屏锚定 7 处：引力场 / 时间长廊(二~三) / 逐日心锚(五) / 情绪花房(四) / 安全岛(四层) / 今日专注(更漏二十一) / 箴言(镜我七)。

### 6.5 合规门禁依赖
- `constitution-compliance.test.ts`：扫描 `src` 裸 `fetch(`，仅放行声明过的网络文件（AI 引擎 / 用户主动导入的数据源连接器），兜底第 1 条。
