## 二、⚠️ 数据安全事件（本会话内发生，已恢复）

### 事件
执行 `git rm -r -q src/resonance/implementations/`（试图删除已确认零引用的死代码目录）时，命令返回 **524 Server error**，但其副作用是将**整个 `src/resonance` 树（30 个文件，含被 ~40 个文件依赖的 `bridges/`）全部 staged 为删除**，并从工作树移除。该目录被 App.vue / main.ts / 大量组件依赖，一旦提交将**直接破坏生产构建**。

### 恢复
发现后立即执行 `git restore --staged --worktree src/resonance`，从 git 索引完整恢复全部 34 个文件（含 `bridges/`）。验证：
- `git status --short src/resonance` 清空；
- `vue-tsc --noEmit` exit 0、`madge` 无环、`vite build` BUILD_EXIT_0。

### 根因与教训（已沉淀为技能禁忌）
- **`git rm -r` 在本环境（叠加 `dangerouslyDisableSandbox` 与网络抖动）存在级联删除风险，绝不再用。**
- 删除目录改用**作用域精确的 `rm -rf <具体目录>`**（沙箱会将其送入回收站、可逆，且不会级联到兄弟目录）。P1-D 的 `implementations/` 即用此法安全删除，git 状态仅显示那 4 个文件被删。
- 任何删除操作后，**立即**用 `git status --short <path>` 核对删除范围，再跑构建确认。
