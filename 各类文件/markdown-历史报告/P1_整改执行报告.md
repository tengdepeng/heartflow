## 2. 循环依赖消除（P1-E）

### 2.1 基线
madge 基线扫描（918 文件）：**9 处循环依赖**。

### 2.2 定性结论
经 Explore 子代理逐项分析，**9 处全部为良性循环依赖**：
- 动态 `import()`（运行时惰性加载，编译期不形成值依赖）；
- `import type`（类型导入，编译后被擦除）；
- 顶层值引用但仅在函数体内使用（ESM 实时绑定延迟求值，无 TDZ 运行时错误）。

即：基线**不存在运行时缺陷**。本次消除循环依赖的目的为「整洁度 + 满足 madge 门禁」，而非修复 bug。

### 2.3 策略：叶子模块抽取（Leaf-Module Extraction）
将 barrel（`index.ts`）中的核心逻辑/状态下沉到独立叶子文件，使 `index.ts` 退化为**纯再导出层**，消费者改为从叶子模块导入，从而打断 barrel ↔ child 的循环引用，同时**完整保留公共 API**。

### 2.4 新建叶子模块（6 个）
- `src/engine/data-port-types.ts` — 抽取 `DataPortPayload` 接口（被 `modules/sync/index.ts` 经 barrel 消费）
- `src/modules/breathing/breathing-core.ts` — 抽取 `useBreathing()` 组合式函数
- `src/modules/craft/craft-store.ts` — 抽取 `useCraftStore` Pinia store
- `src/modules/data-sovereignty/sovereignty-engine.ts` — 抽取主权引擎核心（含 `FORGET_METHODS`、`getSovereigntyConfig`）
- `src/modules/relation/relation-store.ts` — 抽取 `useRelation()`、`persons`、`load`/`save`
- `src/modules/roots/roots-store.ts` — 抽取 `useRoots()`、`roots`、`loadAll`/`saveAll`、`getStats()`

### 2.5 改写/降级为纯再导出的 barrel（3 个）
- `src/modules/craft/index.ts`、`src/modules/breathing/index.ts`、`src/modules/data-sovereignty/index.ts`
- （`relation/index.ts`、`roots/index.ts` 维持聚合式 barrel，仅将 store 实现下沉，保留全部类型/值再导出）

### 2.6 桥接层改指叶子（打断循环的关键）
- `src/modules/craft/craft-bridge.ts` → `'./craft-store'`
- `src/modules/breathing/BreathingLayer.vue` → `'./breathing-core'`
- `src/modules/relation/bond-bridge.ts` → `'./relation-store'`
- `src/modules/roots/root-bridge.ts` → `'./roots-store'`
- `src/modules/data-sovereignty/composables/useForgetting.ts`、`useHallExit.ts` → `'../sovereignty-engine'`

### 2.7 引擎层定向简化（避免全量迁移）
- `src/engine/ai/index.ts`：仅移除 `export { useAIBridge }` 及类型再导出，保留 `aiEngine`（仍被 `stores/advisor.ts`、`resonance/implementations/mirror-ai-capability.ts` 经 barrel 消费）。
- `src/engine/data-port.ts` / `src/engine/data-port-converter.ts`：`DataPortPayload` 改为从 `./data-port-types` 经 `import type` 引入。

### 2.8 结果
madge 复跑（918 文件）：**✔ No circular dependency found!**（MADGE_EXIT=0）。

## 3. 分层违规修复（#1）

**问题**：`src/utils/platform.ts` 的 `triggerHaptic` 通过 `await import('../engine/storage')` 动态依赖 `engine` 层，违反「`utils` 不依赖 `engine`」的分层边界。

**修复**：改为**依赖注入**——`triggerHaptic(intensity, enabled)` 仅在使用方判定是否启用后传参；`navigator.vibrate` 仅在 `enabled` 为真时调用。
- `src/router/index.ts`：`afterEach` 中按配置计算 `enabled`（交互/合规覆盖中的 `hapticFeedback`）后传入。
- `src/stores/timer.ts`：新增 `hapticEnabled()` 助手读取存储配置，两处调用改为 `triggerHaptic('light', hapticEnabled())`。

## 4. 执行中发现并修复的回归（诚实记录）

P1 编辑过程中出现三类编译/类型回归，均已在本轮修正：

1. **`data-port.ts` 游离闭括号**：类型抽取时误留原 `DataPortPayload` 接口的 `}`，导致 `Parsing error: Declaration or statement expected`（ESLint 解析错误）。已删除游离 `}`。
2. **barrel 的 `from` 子句被误删**：`relation/index.ts`、`roots/index.ts` 的 `export type { ... }` 丢失了 `from './relation-network'` / `from './types'` / `from './root-tree'`，变为无来源的本地再导出，触发 `TS2304: Cannot find name`。已补回显式 `from` 子句，barrel 维持纯再导出语义。
3. **叶子文件残留未使用类型导入**：`relation-store.ts`（`RelationNetwork`/`FamilyTree`/`NetworkStats`）、`roots-store.ts`（`TraceTree`/`TraceTreeNode`/`TraceThread`/`TreeStats`/`ThreadReason`）、`data-port.ts`、`data-port-types.ts` 中随抽取产生的未使用类型导入触发 `TS6133`/`TS6196`。已逐一清理。

> 上述回归均在 `vue-tsc --noEmit` 门禁中暴露并修复，未进入最终交付状态。
