## 一、复核口径与方法

### 1.1 为什么旧表不能直接派活

旧表由 `scripts/scan-room-level.mjs` 生成，其「已消费」判据是**标识符集合命中**（`uiSet.has(name)`），
即只要在 `src/components` / `src/views` 里出现同名标识符就算已消费。该判据有三类系统性假阳性：

| 假阳性类型 | 实例 | 说明 |
| --- | --- | --- |
| 前缀碰撞 | `useKnowledgeTower` | UI 里 20 处命中实为 `useKnowledgeTowerUi`（另一个符号）。真实通路是 `useKnowledgeTowerUi.ts:31 const tower = useKnowledgeTower()` |
| 兄弟模块同名符号 | `computeSummary` | `emotion-trends.ts:345` 另有一个同名函数，与 `clepsydra/clepsydra.ts:134` 无关 |
| import 语句误计 | 多行 import 续行 | `timeline-bridge.ts:19 computeTimelineStats,` 只是 import 列表项，不是使用 |

故本次**不沿用旧表判据**，改为 AST 级实证。

### 1.2 本次判据（四层穿透 + 导入解析验证）

对每个候选符号 `S`（定义文件 `F`）：

| 层 | 判据 | 归类 |
| --- | --- | --- |
| L1 | `src/components` / `src/views` 的 `.vue`/`.ts` 内，AST 出现 `S` 的 **Identifier 引用**（排除 import 声明、属性名、定义节点） | **A1 已上盘（直接）** |
| L2 | 非barrel 可达模块文件内 AST 引用，**且该文件的 import 确实从 `F` 引入 `S`**（含经 barrel 透出） | **A2 已上盘（聚合层间接）** |
| L3 | `*-bridge.ts` / `resonance/bridges/*.ts` 内 AST 引用，导入解析验证通过 | **B 假孤儿（bridge）** |
| L4 | `F` 内部除定义行外还有 AST 引用 | **C 文件内自用** |
| L5 | 存在 `getS()` 单例自持有（`let _S` + `function getS()`，且getter 在 `F` 内被引用） | **B 假孤儿（单例）** |
| L6 | 上述全 0，且 `F` 含 `storage.getKV/setKV` 或 `hf:` 键 | **D 真缺口** |

关键实现细节：
- **L2 的「非 barrel 可达」**：从 575 个 UI 入口出发沿 import 传递闭包，但**不让 `index.ts` 充当中转**。若允许 barrel 中转，1074 个模块文件会几乎全部「可达」，判据失效。
- **符号级导入解析**：命中位置必须能通过 import 追溯到 `F`，否则视为同名异物。这消除了兄弟模块同名假阳性。
- 数据背书口径与旧表一致：`storage.getKV/setKV/getItem/setItem` 或 `hf:` 键。

## 六、系统性缺陷：业务日期口径分裂（UTC 切日 vs 官方本地口径）

> 本节由 2026-10-04 的 Timeline 时区修复（`528548c`）引出，**属本报告范围外的独立议题**，
> 单列是因为它影响面远超单个视图，不能当作「一个 bug」处理。

### 6.1 冲突双方

| 口径 | 实现 | 立场 |
| --- | --- | --- |
| **官方（正确）** | `src/utils/time.ts:9` `getLocalDateKey()` | 注释明写：「业务日期**不能**使用 UTC ISO 日期，以避免本地午夜附近跨日」 |
| **违规（ widespread）** | `new Date(ts).toISOString().slice(0,10)` / `.split('T')[0]` | 生产代码 **342 处**（AST 实测，见 §6.5；此前此处记的「195 处」严重偏低，已订正） |

在 UTC+8 下，`toISOString()` 返回的 UTC 日历日在本地 00:00–08:00 恒比本地日历日**早一天**，
故违规写法会让「今天」标签错位、分组跨日错位、按日计数漏计。

⚠️ **但不是所有 `toISOString()` 都是缺陷**——存 `createdAt`/`updatedAt`/`timestamp`
供跨设备传输的 UTC 时间戳是**正确**用法。全仓 2452 处 `toISOString()` 里只有 342 处
是「切日」形态（约 14%），其余不应改。

### 6.4 待修：narrative-generator 的自洽 UTC 簇（约 20 处）

`narrative-generator.ts` 内另有约 20 处 `toISOString().split('T')[0]`，**本轮有意未动**。
原因：它们**内部自洽**——过滤键与调用方传入的 `weekStart`/`weekEnd` 同为 UTC

**只改一半反而会把自洽逻辑改坏**。同理 `timeline-bridge.ts:329`（喂
`generateDailyNarrative`）也须保持 UTC。

⇒ 后续应**成组迁移**：把过滤键 + 全部边界键 + 调用方入参**一起**改为本地口径，
不可逐处替换。涉及 `generateDailyNarrative` / `generateWeeklyReport` /
`generateMonthlyReport` / `generateYearlyReport` / `computeStreakDays` /
`computeEmotionTrend` 六处及其调用方。

#### 6.5.5 结论与建议（2026-10-04 用户拍板：先只出结论，不动代码）

1. **不要机械全量替换**。342 处中约 246 处是真缺陷，但分散在 40+ 域，
   每处都要判「是否自洽」「键存在哪」（有的记录存的是 ISO 字符串，有的存毫秒数），
   逐处机械改风险高于收益。
2. **建议路线**：
   - 先在高收益视图集中区下手（`views/` 57 处 + `home`/`crystal`/`guard-room` 等面板），
     这些「今日统计」的用户可感知度最高；
   - 每批配**反向验证**（改回旧写法确认测试变红）与定向回归；
   - 文件名类（22 处）**明确列入不改清单**，避免无意义 churn；
   - 自洽簇（~37 处）成组迁移，过滤键与边界键一起改。
3. **长期方案建议**：在 `scripts/gates/` 加一道「禁止裸 `toISOString()` 切日」闸门，
   存量进 baseline 白名单，先止血（不再新增）、再按域消化存量。
   ⚠️ 该闸门须精确匹配 `slice(0,10)` / `split('T')[0]` 形态，
   **不可误伤合法的 UTC 时间戳序列化**（那 2452 处里的大多数）。

> **判据提示（适用于后续所有批次）**
> 1. 修这类缺陷必须配「反向验证」（把实现改回旧写法，确认测试变红），
>    否则无法区分「测试通过」与「测试根本没咬住缺陷」。实测两批都有 1–2 例是护栏而非判据。
> 2. **先判自洽性再动手**：若某文件的过滤键与边界键同为违规写法，它内部是自洽的，
>    单独改一处会引入新分裂；须整簇迁移。
> 3. **先验「两种口径是否真的不同」**：加一条前提断言（如「本机是东八区」，
>    否则在 UTC 机器上所有口径断言退化成同值比较而假绿）。
> 4. 警惕「看起来像 bug 的设计」：`Timeline.vue highlightDay()` 的变暗是逐日回看的
>    刻意进度指示，**不是**伪筛选，改成硬筛选反而丢失位置感。
