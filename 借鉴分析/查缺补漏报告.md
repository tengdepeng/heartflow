- 问题：`engine/automation.ts` 运行时导入 `modules/operation-mode/gate`，而 gate 又 `import type { SavedFlow }` 回引 automation，形成环。

### vue-tsc 报错修复
1. **AutoArchivePanel**（TS2783）：`{ enabled: active, ...autoArchiveGateMeta(active) }` 重复指定 `enabled` → 直接返回 `autoArchiveGateMeta(...)`
2. **MirrorSelf**（TS2304）：`ZERO_SAFE` 未导入 → 补 `import { ZERO_SAFE } from '../utils/float-pos'`
3. **App.vue**（TS2322）：`NavTreeNode` 拖拽事件载荷已改为 `targetId: string`，`onMoveNode` 仍按 `NavNode` 处理 → 改为按 id 在导航树中查找节点（新增 `findNavNode`）
4. **App.vue**（TS2345 ×2）：`setRoomPin` 的 `slot/domain` 参数类型收窄为 `RoomSlot | null` / `RoomDomain | null`
5. **NavTreeNode**（TS6133）：`onNavClick` 定义了未接线 → 接到 router-link 的 click（拖拽后拦截误跳转）
6. **FloatingNavBar**（TS2769）：`dragStyle` 空对象返回类型不匹配 `Record<string, string>` → 显式断言
7. **sidebar-interaction.test.ts**（TS2345 ×2）：测试仍用旧版相对坐标 API（`rx/ry/anchor`）→ 更新为像素坐标 `{ x, y }`
8. **constitution.test.ts**（TS2790）：`delete r.scaleScores` 报错 → `ConstitutionScaleResult.scaleScores` 改为可选（运行时 `constitutionRadarData` 本就用 `??` 回退到 `scores*100`）

### 交互逻辑缺陷修复
- **useChromeAutoHide.pokeSidebar**：`if (!sidebarAutoHidden.value) sidebarAutoHidden.value = false` 逻辑写反——侧栏已自动隐藏时调用不会复位，导致「对侧栏操作 → 在原位置出现」失效。改为 `if (sidebarAutoHidden.value)`，sidebar-interaction 测试 ④ 由红转绿。
